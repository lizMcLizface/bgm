## Preserved clocks and DSP

The original30ms Float32 target recurrence, original-seconds comparisons, retained-event pruning and nominal tone-frequency output clipping/intrinsic carry remain explicit.

A ready curve is read by reference, so switching its index preserves every FIR history sample. The original2049point curve is prepared using the exact original JS `Math.tanh` law outside rendering; this preparation boundary is disclosed, not claimed as Rust-only preparation. The portable Rust instance accepts immutable Float32 resources. No live Native gain/filter/LFO coefficient is passed into Rust.

The FIR group delay is128frames. The original6ms base delay and wow/flutter wet modulation are actual effect timing, not invented PDC latency. Float32/SSE-style delay read positions and the pinned Native sine tables preserve the existing explicit arithmetic profile. Native connection-order variation means bounded empirical Native PCM coverage is not a universal bit-identity guarantee.

## Bounded resources and ordered controls

Every instance preallocates32physical curves of2049Float32 values (262272data bytes), fixed scratch space and32ordered control records. Curve generations increase without wrap. Uploading, ready, active and referenced resources have distinct ownership; queued/active resources cannot be reclaimed. Ready data is immutable. Whole chunks validate before any data/budget mutation. Each declared service ordinal admits at most1024copied floats; repeated ordinals reject. Curve activation is O(1), and reclamation preserves generation identity. The normal full-preset reservation is eight original records: wow2, rate2, flutter2, drive1 and tone1. Capacity refusal occurs before caller control mutation. A queued curve that is not ready prevents the entire control batch from committing; rendering such a pending batch refuses instead of silently using the old curve or applying later controls out of order.

The NEW resource-only worklet has no audio inputs and never invokes DSP rendering. It services a fixed two-entry chunk queue, consumes at most one chunk of at most1024floats per actual callback and returns explicit upload credits. The main preparer permits at most two transferred chunks without ACK, retains at most32leases and waits for reclamation ACK before generation reuse. Its5second preparation/release deadline bounds stalled requests. This is a resource-preparation service, not an audio Tape facade or evidence that asynchronous curve installation matches an unsuspended Native assignment clock.

Eleven per-node activity modes separately govern shaper, lowpass, delay, four oscillator bodies and four depth gains. Mode0 is unpulled, mode1 processes that node's parameters only and mode2 processes its body. An explicit empty-input FIR body call drains history with zeros; it does not inherit Motion's whole-stage empty-input policy. Actual automatic Native tail transitions still need their own source-derived/desktop proof. Numeric zero alone cannot establish Native AudioBus silence or body activity.
