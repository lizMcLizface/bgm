# Stamped authored target transport

## Why the original transport was insufficient

The v1 rack metadata protocol used independent AudioParams for targets, frame words, initial flags and a sequence commit. Writing the commit last on the main thread does not make independently evaluated AudioParam fields an atomic render-thread snapshot. A callback can see a higher record tag while an earlier record is still old, or a commit tag while some payload fields are old.

Actual normal All review retained two failure modes: `owned-host-dynamics-sequence-first.json` completes two hosts before the restored third fails with a sequence gap; diagnostics-only `owned-host-dynamics-diagnostic-fb18.json` fails preparation with backwards authored chronology after21 observed records and28 posted records. That capture also exposed an arm-after-disposal TypeError masking the original transport failure; arming now returns the retained primary failure. Its reader diagnostics did not identify the exact torn field, so no exact field-level native trace is claimed.

Independent permanent v1 tests enumerate all64 combinations of a normal record's independent fields and demonstrate both safe refusal and silent old-payload consumption. ACK-before-reuse bounds total outstanding records but cannot prove publication completeness by itself. The original v1 helper remains for explicit negative proofs and synthetic cost comparison; the current rack factory uses the stamped profile.

The earlier context-binding startup failure was a separate review-page issue. Vite's special `?v=dynamics*` module query propagated into some shared AudioContext imports while other cached transforms used the canonical URL. Strict context binding correctly rejected the two different instances. The review entry now uses neutral `?review=...`; evidence is in `rack-dynamics-dev-import-urls.txt`. No context guard was weakened. The first review tool also overwrote its primary failure with a secondary missing-owner check; primary errors/stacks are now retained, with secondary checks recorded separately.

## Complete publication without checksums

`stampedRackTargetTransport.js` exports `stampedRackTargetDescriptors`, `StampedRackTargetWriter` and `StampedRackTargetReader`. All AudioParams carry authored integer metadata only; Rust still owns smoothing and DSP. No pulled Native coefficient/value bridge is used.

Each packed field is an exactly representable24-bit integer: an8-bit sequence stamp and a16-bit payload word. A raw Float32 target uses two words; the original bounded40-bit canonical frame uses three; the initial flag has its own stamped word. A separate full24-bit sequence remains monotonic and refuses exhaustion before wrap. Normal records retain both lane identity and target. Original per-leaf `currentTime` reads, Native target-law timestamps, repeated calls and initial/target distinctions are preserved.

The reader validates every word stamp before decoding or consuming that record. It copies only a complete contiguous prefix into its preallocated owned arrays and ACKs only after copying/application. Incomplete tags or words defer the record and everything after it; they are not skipped or coalesced. Invalid integer fields, range violations, future/backwards epochs and true overwrite still fail closed. Deferred counts/reason/word/streak and late-delivery frames are explicit statistics. A late complete record retains its original called timestamp; no timestamp rebasing or PCM alignment shift is applied. Native unsuspended dispatch can differ from the time a complete metadata record is observable, so universal unsuspended Native bit parity is not claimed.

There are at most64 outstanding slots, strictly fewer than the256 stamp period. Before a slot can be reused, its previous record must have been copied and ACKed with every word's previous stamp. Its next reuse differs by the slot count, which is less than256. A stale word therefore cannot match that next record's stamp. It cannot survive enough unacknowledged reuses to alias a later same stamp because the writer refuses at the outstanding bound. Duplicate/late ACKs never move the watermark backwards or acknowledge an unposted future sequence. Tests exercise the zero-stamp boundary at256 with one stale word while attempting to lap the withheld ACK.

The writer API remains bounded: `preflight(count, firstSeconds)` reserves capacity for a whole original GUI patch before any target mutation, `post(values,{initial,seconds})` records one authored micro-operation, and `acknowledge(sequence)` advances only a valid watermark. `read(parameters,effectiveCanonicalFrame)` returns the complete count, with `.frames`, `.values`, `.initials` and `.sequence` retaining the existing adapter shape. Readiness/flush requests remain bounded; a permanently incomplete record cannot receive an ACK and eventually causes explicit capacity or acknowledgement failure.

## Resources and cost

The normal2-lane32-slot profile has289 AudioParams including Boolean demand, up from193. The atomic7-lane8-slot profile has153, up from89. Writer/reader typed arrays, Float32 bit-conversion storage and field names are prepared up front. Rendering validates/copies within fixed capacities; no Rust allocation, reclamation or memory growth is introduced.

Actual desktop Native AudioParam cost was measured in eight synthetic muted OfflineAudioContexts at48kHz, two repeats/profile, each rendering96,000 frames. Normal render wall times were84.6/86.6ms for193 parameters and139.9/147.7ms for289; largest observed supplied parameter arrays grew from7,884 to33,160bytes. Atomic times were48.5/33.3ms for89 and73.4/63ms for153; supplied arrays grew from1,372 to10,264bytes. These are observed parameter-array storage and preemptible wall times under synthetic prebooked controls, not total Native heap, device deadlines or CPU utilization. Report: `reports/modular_audio/rack-dynamics-stamped-cost.json`. This extra metadata overhead remains a concrete headroom risk for an untested multi-node phone profile.

The actual public stamped processors also pass audited Rust checks: normal12 cases/12,000 callbacks/62,592 records and atomic24 cases/24,000 callbacks/25,344 records/96 resets, with zero Rust allocation/reclamation/growth. Reports: `rack-dynamics-stamped-normal-allocation.json` and `rack-dynamics-stamped-worklet-allocation.json`. Synthetic normal NodeVM largest median is0.1116ms, p95 is0.1959ms and largest callback1.2788ms; Native AudioParam serialization and physical deadlines are excluded.
