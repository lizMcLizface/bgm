# Filter rack activity admission

This new pure planner is separate from normal environment selection. It does not infer native silent flags from PCM, node connectivity or a source backend name. The accepted Filter component retains its independent explicit-activity contract; the planner currently selects only its narrower continuous-program authority.

`planFilterRackActivity({rate,source,stages,stageContracts})` validates a complete proposed ordered topology and returns a frozen detached plan. Stages have unique concrete IDs and kinds (maximum64). If no owned Filter is requested, the plan makes no source-activity claim. Otherwise the rate must be44100/48000/96000/192000 and the caller must declare a fixed mono/stereo active program, a concrete source identity and monotonic revision, positive unit source gate1, and no source lease. Active numerical zeros are supported by that declared source; arbitrary native silence/tail flags are not.

Every prefix before the last Filter needs an explicit identity-bound contract asserting active-program input/output and a fixed preserve/mono/stereo layout. No contract is inferred for a compressor, space bus, drive, effect or bypassed stage. An earlier admitted Filter itself preserves the declared program. Suffixes after the last Filter need no activity contract for this particular admission decision. A contract is a trusted caller assertion tied to its actual implementation, not evidence that arbitrary Native nodes satisfy it.

`preflightFilterRackTransition(current,proposal)` validates the whole proposal before a caller changes settings, wires nodes, edits source gates, creates a new stage or changes a lease. It also rejects backwards revisions for the same active source. `assertFilterSourceLeaseAllowed(plan)` must run before a source owner silences its original node or injects replacement material. It refuses a lease while an owned Filter declaration is active. This API is not a rollback mechanism; existing Graph callers do not yet invoke it and their ordering must be reviewed before integration.

A complete owned chain is sufficient but not strictly required. A narrowly certified active source with Filter first can also supply its authority. Normal rack input trim uses a positive10**(dB/20) coefficient, but native source gates and preceding effects can still change activity. In particular, Classic `holdSourceInput()` sets nativeGate.gain to0 and then admits finite replacement material; Rust source identity alone cannot certify that transition. Unsupported prefixes, topology changes and leases must be explicitly refused before mutation or supplied with a source-faithful activity plan. No hidden Native fallback is proposed.

## Verification

The pure planner has34 focused tests for supported rates, identity/revision/layout/gate/lease admission, unknown prefixes including bypassed stages, concrete contract binding, bounds, detached frozen plans, backwards revisions, whole-proposal preflight and refusal before mutation. New tools/filter-rack-activity.html adds six pure refusal checks and two48k original-native output comparisons: first Filter and an explicitly declared owned Width prefix before Filter. Each actual case uses two independent owned instances and Native StereoPanner routing, and attempts invalid prefix/reorder, source lease and source gate edits during playback. The fixture records that no settings/wiring/gate/lease/stage-creation mutation occurred after those refusals. The actual desktop admission fixture passed both first-Filter and declared owned-Width-prefix comparisons with exact Native PCM and exact independent owned instances. All six pure refusals and all in-render refusal-before-mutation counters passed; filter-activity-admission-first.json retains the full evidence. The accepted Filter32-case results are recorded in the separate component document.

The review uses a caller-authored continuously active AudioWorklet source, including its own output activity contract. It does not exercise the normal All/CLASSIC source-lease API or select a prepared environment. Shared createRack, extras, source owners and environment code remain unchanged.
