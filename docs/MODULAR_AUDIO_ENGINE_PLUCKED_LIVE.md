## Actual material and boundary

This is the existing `stringModel:'plucked'` Karplus–Strong path, not the measured cello Long/Live/Short/Pizzicato model. The five active catalog presets are Nylon Guitar, Soft Harp, Harp Pluck, Kalimba Pluck and Upright Pluck. Their actual catalog `stringPatch` adaptation, settings, seeds, filters and body modes are used; their separate oscillator “classic” variants remain unchanged.

The native chain is original `stringBuffer`/`renderString` material → AudioBufferSource → source gain 2.5 → physical-slot gain envelope → Biquad → volume 0.2 → original instrument mixer/effect rack. The owned implementation preserves that boundary, live held-note release, source stealing, native buffer fractional onset/rate/stop laws, all seven filters, pitch expression, shared modulation and the independent original air branch. It does not insert a piano model or use piano preparation to generate KS material.

The shared physical buffer player reuses the accepted, bank-agnostic Rust PCM/slot/timeline/filter/air kernel. Its historical `piano_live_*` ABI export names remain compatibility names only. `OwnedPhysicalBufferLive` and the generic processor receive material explicitly, while `createPluckedLiveSource` accepts only actual `plan.string` and strict `material:'plucked'` worker results. Piano-labeled prepared resources and piano note plans reject. A future piano wrapper can share this controller without copying its timing/lifecycle behavior; the currently accepted piano controller is retained during validation.

## Preparation and ownership

`pluckedLivePreparation.worker.js` uses the actual accepted `OwnedPluckedString` preparation. It reproduces the original 0.01 Hz stringBuffer cache pitch quantization, seeded f64 KS feedback/noise/body/filter operations and f32 write/normalization order. Original note settings remain pure data. Each controller has independent bounded preparation workers; no JavaScript preparation fallback or native AudioBuffer is used by the owned source. Worker results are copied from owned Wasm then transferred, and preparation handles are freed off the render path.

`physicalBufferLiveSource.js` owns its resource identity/cache/pins, atomic action batches, actual processor, normal wake/sleep, modulation control, live release, failure and disposal. Separate `public/physical-buffer-live` assets give the generic runtime exact provenance without changing the accepted piano asset manifest during initial development. Module code may be shared; instances, Wasm memories, queues and source cursors are independent.

The original bounds remain: 32 physical slots, 2,000 sources/pending bookings, 128 resource banks, 64 MiB prepared kernel material and a 24 MiB host cache. FIFO reservations pin resources until actual booking/cancellation; LRU eviction cannot reorder cold bookings. Overcommit rejects explicitly. Successful render/cancel/reset paths allocate/free/grow nothing in the Rust kernel. Shared HostRenderClock translates the measured native advancing-callback law while retaining strict raw epoch and stale-lag bounds.

## Normal host API

`new Instrument({context,preset,polyphony,sourceBackend:'owned-rust'})` selects the explicit owned KS source when the actual preset has `stringModel:'plucked'`. Await `sourceReady`; after cold scheduled notes, await `awaitPendingSourceBookings()` and call `prepareOffline()` before offline rendering. `startNote`/`stopNote`, pending-key release policy, silence, stale held IDs and per-slot stealing remain original host behavior. Native defaults and saved song data contain no backend flag.

The new `pluckedSource` is distinct from `pianoSource`; `isOwnedPluckedPreset` checks the exact existing source kind. Shared Instrument lifecycle operations select the actual owned source without changing the accepted piano controller. Changing material on one owned physical instance requires a fresh instrument so two source engines cannot feed the same rack accidentally.

`sourceStatus()` reports material, pending bookings, source health and a bounded host booking trace. Scheduled records preserve requested, guarded and actual MonoSynth-committed onsets, preparation-ready frame and guard-shift frames. `preparationLateFrames`/`preparationLateBookings` report the real live guard shift separately from kernel late-event statistics. Offline timestamps retain authored zero exactly. These bookkeeping fields are transient runtime state, never preset mutations. Direct `setDrift` updates now synchronize the owned controls immediately.
