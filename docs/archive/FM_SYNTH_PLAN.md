# FM backend laboratory

18 October 2026 — playable operator FM with expression, common instrument inserts and per-note acoustic textures. Standalone editor: `/tools/fm.html`; public audition workspace: `/labs/` with five instrument families. The main generator has an experimental Wasm adapter, off by default. Its existing flat preset format remains; FM-marked sounds translate into operator patches, while full laboratory FM patches can be auditioned/imported in the instrument benches.

## Implemented

- Original, dependency-free Rust DSP in `synth-engine/fm/`, compiled independently to `public/synth-lab/fm.wasm`. No web-synth, Dexed, factory patch bank or external sample ROM is incorporated.
- Four or six phase-modulated operators per note, up to 32 independent note IDs, sustain, release-aware voice stealing, panic and a bounded sample-timestamp queue. The same note/event bridge contract as the subtractive engine includes continuous per-note retuning without restarting the envelopes.
- Ratio or fixed-frequency oscillators, detune, operator output/modulation levels, one selected feedback loop, and a global modulation index. Six starting topologies cover serial, parallel-stack, pair/converging, additive, branched and long-stack-plus-pair layouts. The visible forward routing matrix and carrier weights can extend those layouts. Operators are evaluated in ascending order; feedback is the explicit delayed loop, not arbitrary instantaneous cycles.
- Per-operator four-stage time/level envelopes: rise to peak, decay to a breakpoint, second decay to the held level, release to zero. Parameters are seconds and normalized levels, rather than the DX7's hardware rate/level encoding. Velocity, keyboard level/rate scaling, carrier pan and pressure-to-level provide performance control. LFO pitch/amplitude/index motion, pitch bend, mod wheel and a short pitch envelope are global controls.
- Sine plus three simple non-sine variations, phase-reset/free-phase choice, and 1×/2×/4× rendering. Oversampled modes use a normalized windowed-sinc FIR before decimation; the selected feedback delays stay one/two output-sample periods across quality modes. Output saturation is inside the oversampled path. Oversampling reduces some aliasing; high operator ratios, depth and feedback can still create it. It is not a guarantee of hardware accuracy or identical timbre at every setting.
- Eleven original recipes: Tine constellation, Glass satellites, Four-op round bass, Breathing FM brass, Bowed glass pad, Parallel drawbars, Fixed orbit bells, Four-op hollow reed, Living glass, Air choir and Air reed. The first nine retain their earlier settings; new acoustic recipes demonstrate per-note excitation/formants/body.
- Four signed per-voice modulation routes, a separate modulation envelope, LFO 2, smooth random motion/drift and per-operator attack/decay/release curve multipliers. Sources can affect pitch, index, feedback, amplitude, stereo balance or individual operator levels. Numeric IDs append to the original ABI: 54 global and 21 operator fields, API/patch version 1. Default curve multiplier 1 preserves the original contour; new routes/drift default off.
- Per-note acoustic colour adds envelope/pressure-shaped air/friction excitation, continuous vowel formants and fixed four-mode body resonance. Thirteen appended global controls default to neutral. Resonance release tails retain voice/source lifetime; see the checkpoint below.
- Optional instrument inserts use a separate shared implementation: saturation, three-band EQ, phaser, flanger and stereo chorus before echo/room sends. They are per instrument, not per note or inside the FM oversampling loop. Patch JSON retains the optional settings. Existing room sharing/private-room requests remain intact.
- Live pointer/computer-keyboard playing, sustain, shared reverb/delay, patch JSON import/export, audio/WAV comparison and JSON benchmark reports. A held-chord passage glides four note IDs through new pitches after one attack. The quality comparison uses identical settings/events and shared playback cursors with bar labels. Dry is the benchmark default; wet comparisons include conservative effect tails.

## Architectural references and boundaries

The four/six-operator approach follows the broad Yamaha DX/TX tradition, not its ROM, chip arithmetic or patch encoding. [Yamaha's FM-X overview](https://europe.yamaha.com/en/musical-instruments/keyboards/explore/montage-portal/essentials/fm-x.html) contrasts the DX7's six operators/32 algorithms with later FM-X designs. This laboratory currently offers six topology families and custom forward routing. They are not numbered reproductions of those 32 DX7 algorithms. Its non-sine operators are extensions, not a recreation of all TX81Z waveforms. SysEx compatibility, exact hardware envelopes, original lookup tables and comprehensive DX algorithm import are outside this slice.

The engine is phase modulation in the usual digital-FM sense. Operator amplitude/envelope changes alter the modulation index as well as carrier loudness. Fixed-frequency operators do not transpose with a note's ratio-frequency glide. The operator carrier mix is normalized by carrier weights and passed through a bounded output stage. A level change is therefore not an exact copy of a hardware output-level scale.

The backend runs on the AudioContext's single audio rendering thread. Multiple worklet nodes do not create a CPU pool. A future worker/SAB pipeline could distribute work with explicit buffering and scheduling; the callback must never block on workers, and deployment needs appropriate cross-origin isolation for shared memory. [Chrome's design patterns](https://developer.chrome.com/blog/audio-worklet-design-pattern) describe the buffered-worker approach. The live backend adds no worker pool, additional live AudioContexts, isolation-header changes or automatic quality policy. Offline comparison pages use ordinary Workers.

### Note contract

Both original Rust kernels now use the same fixed-capacity last-key-priority logic, called at the scheduled sample frame. Modes are polyphonic, mono retrigger and mono legato. Mono uses one voice while remembering up to 32 keys; excess keys forget the oldest entry and its later release is harmless. Releasing the selected key returns to the latest still-down key. Sustain retains released keys only while the pedal is down, preferring physically held keys; pedal release clears latched entries and releases the last voice if none remain. Stale releases and repeated pitches use IDs. Panic clears the key stack, pedal and future note/patch events. A mode change clears held voices/key state while preserving subsequent scheduled notes.

Legato preserves oscillators, filters, envelopes and per-voice texture on overlapping keys. Mono retrigger restarts amplitude/filter/modulation or operator/expression envelopes; the short existing-output fade bounds the attack discontinuity. FM operator phase-reset follows its existing key-sync setting on retriggers; legato keeps phases running. A gap starts a fresh envelope attack. Portamento is fixed-time, linear in semitones, 0–3 seconds, and can apply only to overlaps or also across separated mono notes. Its first-ever note starts directly at the requested pitch. Explicit held-ID retune events remain available independently, including in polyphonic mode.

Patch JSON version 1 gains an additive `performance: {mode, portamento, glide}` field. Missing/null performance imports as polyphonic, zero portamento and overlap-only glide. Numeric global/layer/operator parameter IDs are unchanged. Additive event kind 6 is `[6, mode, frame, portamentoSeconds, allNotesGlideFlag]`; the original ABI version and other event meanings remain. The new shared Rust notes module participates in both source hashes.

### Patch contract and limits

The common worklet transition controller interpolates changed continuous controls on a deterministic 16-sample grid, using logarithmic paths for applicable positive frequency/time/ratio controls and smoothstep interpolation. Requests can be timed ahead with `backend.patch(patch, {time, seconds})`; default live edits take 60 ms, positive durations are bounded to 16 ms–2 seconds, and zero explicitly selects the preceding immediate behavior. Discrete controls switch at the midpoint with a short 4 ms down/4 ms up output duck; interrupted ducks have bounded gain slew. Rapid edits retarget from the current control values; same-frame queued edits coalesce and the future patch queue is bounded at 32. Panic/dispose cancels active and pending transitions. Steady rendering uses the existing output-copy path when no transition is active; no second synth instance is crossfaded in or retained.

This smooths source parameters, not entire effects graphs or arbitrary prepared-buffer replacements. Architecture/capacity/operator-count/quality changes retain their existing restart/held-note-clear limitations; the continuous morph comparison keeps the architecture and FM quality fixed. Piano/pluck/percussion remain on the specialized native adapter with prepared-note polyphony and held resampled retuning; the new analog/FM legato and parameter-morph semantics are not claimed for those buffers. The generator/backend migration and preset UI remain separate integration work. Main-generator presets, composition, sound choices, room ownership, and the approved 2x FM default are unchanged; chip articulation remains excluded.
