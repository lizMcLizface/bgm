# Exact Native single-harmonic preparation

This small preparation-only port reproduces the actual custom `PeriodicWave` operation order used by the original Ambience wander source. It replaces the former assumption that two captured sine/cosine basis tables could be combined after preparation with identical Float32 results. That assumption failed the unchanged high-rate control bound by one Float32 step; the retained actual evidence is `ambience-spatial-v4-shard2.json`.

The pinned Chromium `FFTFrame` wrapper uses RustFFT6.4.1. This explicit profile ports only its selected f32 AVX/FMA inverse recipes needed for a single harmonic at table sizes 2,048, 4,096 and 16,384. The implementation is 268 Rust code lines, has no external dependencies, and does not vendor a general FFT library or embed captured output tables. It preserves even inverse packing, radix4/8/32/256 operation order, the asymmetric fused complex multiplications, specialized eighth-root rotations, and the two distinct inverse/normalization scale operations. Scalar complex lanes use IEEE fused `f32::mul_add` to retain the selected AVX arithmetic order in portable Wasm.

`prepare(size, real, imag)` accepts finite Float32 phase coefficients within [-1,1], rejects unsupported sizes before allocation, and returns the owned table. The standalone ABI and JS adapter provide the same bounded cold-preparation contract. Preparation allocates bounded temporary arrays and releases them before returning the table; this is not audio-callback work. Independent handles own independent tables. There is no global mutable plan/cache and no browser DSP dependency. The Spatial dependency disables the standalone ABI feature, so no unrelated exports are required by that kernel.

The actual diagnostic `/tools/ambience-spatial-phase.html` uses unchanged original `wanderLfo` creation, then exact integer table reads. All second periods must match the first bit for bit. Its independent zero-phase captures must match the existing immutable Native sine resources. The actual three-context/eight-recipe capture passed those authority checks at all three table sizes. Full evidence remains local in `reports/modular_audio/ambience-spatial-phase-first.json`; the permanent fixture retains only 24 input recipes and SHA256 outputs, plus the full report's identity. Every prepared table from this Rust port matches its actual Native authority bit for bit: 24/24 tables, zero differing samples and zero maximum error. No phase/gain fit, PCM edits, normalization adjustment or tolerance change was applied.

The standalone production identity is `4860b39374a17ea2` (34,046-byte Wasm; SHA256 `bce50df801f5ffd1aa2d296643fdcad4b15f4ec379ae952bce1f61ccef4136e0`). Four focused tests verify all24 actual table hashes, invalid requests before any Wasm call, strict raw-ABI coefficient bounds, independent handles, JSON coefficient reconstruction, a4MiB cold workspace bound and stable table reads. Spatial integrates this preparation only after that bitwise authority proof.

This is a named pinned arithmetic profile, not a claim that every browser CPU's runtime-selected FFT planner produces identical bits. Other Native SIMD/scalar planners and general multi-harmonic FFT input remain outside its contract. Existing app/normal source choices are unchanged.

Build: `node tools/buildNativeWavePreparation.mjs --publish`; add `--check` for source/runtime/authority provenance. Focused proof: `npm.cmd exec vitest run src/modular-audio/nativeWavePreparation.test.js`. Exact primary-source identities and upstream licenses are retained in the crate's `CHROMIUM_PROFILE.json` and `CHROMIUM_NOTICES.txt`.

The final integrated Spatial36-case six-rate group also passed after this helper was adopted: every wet layer bit exact and every drift control numerically exact. This is downstream confirmation in addition to the independent24-table bitwise preparation authority.
