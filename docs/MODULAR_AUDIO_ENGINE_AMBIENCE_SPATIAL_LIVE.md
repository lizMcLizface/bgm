The standalone live processing pool is accepted on host `df07388db386f9a0` and live kernel `456b8b06217bed36`. A context owner cold-prepares a bounded number of bed slots while the AudioContext is suspended (two by default, explicitly capped). Each slot retains its six-layer Rust engine and preallocated table staging. Running acquisition uses an idle prepared slot and refuses before mutation if none is available. Releasing one bed returns only its slot; it cannot retire another bed's resources or the context pool. Context retirement remains the context owner's responsibility. There is no hidden suspend/resume or first large allocation on an active audio thread.

A separate context-owned zero-input clock processor drains resource uploads without pulling any bed's audio inputs. Pinned AudioWorkletHandler automatically pulls a node whose outputs have no connections, so a dormant bed retains an edge to a passive disconnected sink; this prevents automatic pull without creating a destination path. The actual bed input/output bridges are lease-specific and disconnect on release. Recorded upstream source edges also detach on logical unplug so shared reader demand cannot advance a dormant bed's cursors. The actual six-layer lifecycle group below verifies this topology and independent pull clocks. At cold suspended startup, a bounded MessagePort pump can upload resources before callbacks exist. After callbacks begin, uploads drain at most one1,024-float chunk per callback, with at most two transfer buffers in flight. Source/rack PCM continues while new resources prepare. Every receiver chunk is echoed and the full readback identity is checked before sealing a resource. Canceled generations and capacity failures cannot overwrite an active table.

The exact single-harmonic preparation helper runs offthread. A layer's phase-table key is determined by its immutable constructor phase, piece offset and constructor period; it does not depend on the eventual constructor clock. The active and staging table buffers are allocated cold. A complete staged table swaps into an unused layer at its acknowledged constructor epoch, with no allocation/free or large whole-table copy in a callback. Global wander changes before a layer exists affect its eventual constructor recipe; existing layers preserve their original phase table and apply frequency changes through the original parameter timeline.

The new independent control-preparation crate keeps a transactional forecast of the original WalkPath. Preparing a candidate operates on copied bounded state. Publication acknowledgement alone advances the committed random stream. A huge overdue refill or overlapping pending request refuses before committed state changes. Cancellation leaves the prior source and random sequence intact. Commands are applied in original call order; preparation completion order cannot reorder actual settings.

This avoids pre-rounding relative event times or guessing the constructor epoch. Refill resources know the acknowledged origin and carry index/value pairs, preserving the same expression and original period-at-booking behavior. A later period changes only undrawn knots.

The offthread facade stores a bounded journal of committed recipe/period/booking operations. JSON reconstruction reproduces the same future knot values and draw counts; pending resources must be acknowledged or canceled before saving. This is deterministic control preparation replay, not serialization of in-flight audio/IIR state.
