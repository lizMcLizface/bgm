# Owned Ambience live preparation — candidate design

The accepted finite processing payload and its36 Native cases remain unchanged while this candidate is developed. This slice adds resource preparation and admission; it does not change app defaults or normal Ambience yet.

A context owner cold-prepares a bounded number of bed slots while the AudioContext is suspended (two by default, explicitly capped). Each slot retains its six-layer Rust engine and preallocated table staging. Running acquisition uses an idle prepared slot and refuses before mutation if none is available. Releasing one bed returns only its slot; it cannot retire another bed's resources or the context pool. Context retirement remains the context owner's responsibility. There is no hidden suspend/resume or first large allocation on an active audio thread.

A separate context-owned zero-input clock processor drains resource uploads without pulling any bed's audio inputs. Pinned AudioWorkletHandler automatically pulls a node whose outputs have no connections, so a dormant bed retains an edge to a passive disconnected sink; this prevents automatic pull without creating a destination path. The actual bed input/output bridges are lease-specific and disconnect on release. Recorded upstream source edges also detach on logical unplug so shared reader demand cannot advance a dormant bed's cursors. This topology still requires actual Native pull/unplug verification. At cold suspended startup, a bounded MessagePort pump can upload resources before callbacks exist. After callbacks begin, uploads drain at most one1,024-float chunk per callback, with at most two transfer buffers in flight. Source/rack PCM continues while new resources prepare. Every receiver chunk is echoed and the full readback identity is checked before sealing a resource. Canceled generations and capacity failures cannot overwrite an active table.

The exact single-harmonic preparation helper runs offthread. A layer's phase-table key is determined by its immutable constructor phase, piece offset and constructor period; it does not depend on the eventual constructor clock. The active and staging table buffers are allocated cold. A complete staged table swaps into an unused layer at its acknowledged constructor epoch, with no allocation/free or large whole-table copy in a callback. Global wander changes before a layer exists affect its eventual constructor recipe; existing layers preserve their original phase table and apply frequency changes through the original parameter timeline.

The new independent control-preparation crate keeps a transactional forecast of the original WalkPath. Preparing a candidate operates on copied bounded state. Publication acknowledgement alone advances the committed random stream. A huge overdue refill or overlapping pending request refuses before committed state changes. Cancellation leaves the prior source and random sequence intact. Commands are applied in original call order; preparation completion order cannot reorder actual settings.

First-booking resources include a one-knot guard prefix around the nominal90-second horizon. The actual constructor's left-associated Native timestamp expression (`birth +index*2 -offset`) selects the exact published prefix, and the producer commits the matching saved RNG state. This avoids pre-rounding relative event times or guessing the constructor epoch. Refill resources know the acknowledged origin and carry index/value pairs, preserving the same expression and original period-at-booking behavior. A later period changes only undrawn knots.

The offthread facade stores a bounded journal of committed recipe/period/booking operations. JSON reconstruction reproduces the same future knot values and draw counts; pending resources must be acknowledged or canceled before saving. This is deterministic control preparation replay, not serialization of in-flight audio/IIR state. Runtime stream identities and generations remain outside song data and reject acknowledgements from a different lease.

Private proof currently covers24 first-booking cases,960 subsequent timer refills and8,277 exact Float64 points against unchanged original JS, at six rates with offsets0/17.3/89.25/1,000,000 and period edits. All original draw counts match. Huge-gap refusal preserves the committed state; independent facade JSON replay, cancellation and reset also pass. No public live payload or Native host acceptance is claimed yet.

The proposed worklet resource extension is feature-gated so the accepted default finite numerical payload remains byte-identical. Actual candidate QA must cover suspended startup, running new-layer installation, repeated period/mode changes, overdue/canceled uploads, two independent beds, disposal of one bed while the other plays, reused contexts, exact source/rack clocks and bounded allocation/upload behavior. Native filtered endpoint flags and full app adoption are judged separately; there is no PCM-magnitude silence inference.

The new independent control producer also owns phase recipe arithmetic and matches all21 nonzero-phase Native recipe hashes. Its first/79refills/refusal/reset allocator audit reports zero allocations/frees/growth after planner creation; exact table generation remains explicitly offthread preparation. The accepted finite numerical payload remains unchanged; source additions are separately feature-gated below.

## Receiver and admission checkpoint

The feature-gated receiver now exists separately from the accepted default payload. Its facade cold-allocates the original processing core plus seven retained phase staging banks and seven bounded knot staging banks. Unknown phase and Brownian resources arrive from the standalone offthread producer. Installation swaps an already allocated table pointer and copies only the bounded knot records into retained lanes. Phase-only preparation draws no Brownian state; switching an existing sine to its first walk prepares the walk only when requested. First-walk mode/period/depth publication has one preflight, so lane exhaustion does not consume the staged resource or change the active sine.

Commands and timer refills carry a captured canonical main-thread observation frame, separately from their original event seconds and the audio render cursor. Insertion admission/pruning uses that authored observation rather than a delayed receiver callback. A dedicated live-only state field tracks successful authored observations; same-frame calls preserve order and nonzero-origin lease reset establishes a fresh minimum. Successful observations must remain monotonic; malformed, stale or over-capacity requests refuse before active state mutation. No missing audio age is synthesized. Existing finite configuration, command and reset behavior remains the default; live handles reject the legacy unbounded-seek command/reset entry points and use explicit retained-storage lease reset instead.

The context-wide upload receiver has exactly two4,096-byte transferable credits. It drains at most one1,024-float phase chunk per actual128-frame callback. Explicit suspended-startup message pumps drain one bounded packet at a time before callbacks exist; no process-only wait or hidden context resume is required. Full actual receiver readback SHA is checked offthread before sealing staging. Generation retirement returns stale credits and retires only staging, leaving active processing state intact. Resource capacity is32 pending records; stream identity is bounded by16 slots times seven waves. These are standalone protocol checks, not proof of browser context topology yet.

Sixteen focused permanent checks pass across receiver, producer and core. They include480 canonical quanta with every wet stem/control exactly matching the accepted finite kernel at six rates and both drift modes; an additional six-rate sine-to-first-Brownian switch; malformed/overlapping/legacy refusal, bounded future-lane exhaustion, independent lease reuse, captured observation clocks, actual Wasm staging/readback, suspended upload and cancellation. The live allocator audit covers phase publication, first booking,1,500 rolling commands,79 refills, cancellation and lease reset with zero Rust allocations, frees or memory growth after cold creation. A cold192kHz slot currently occupies6,619,136 bytes of Wasm memory.

The default `spatial.wasm` remains exactly208,078 bytes with SHA256 `382cc1793fb37b8ab9740a9220cb956b2e394f20145337faa1b86863623dd1c3`, identical to accepted `a29f14476cc6f07d`. Its manifest changes only to describe the new feature-gated source. The default literal method bodies and source positions are preserved; feature implementations are appended separately because even a semantically neutral helper changed optimized control flow and panic-location bytes in an initial private build. That private difference was not published. The separately built `public/ambience-spatial-live/live.wasm` never replaces the default binary.

Build the receiver using `node tools/buildAmbienceSpatialLive.mjs --publish` / `--publish --check`, and audit using `node tools/auditAmbienceSpatialLive.mjs`. Native live worklet topology, fresh/reused context clocks, context-owned pool lifecycle and normal app adoption remain unaccepted candidate work. The original finite36-case Native proof remains attached to its accepted numerical identity; it is not presented as a live browser proof.
