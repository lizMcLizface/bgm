# Selected complete Ambience cold startup

These new adapter leaves prepare an explicitly selected complete live Ambience profile. Existing Ambience, its normal backend selection, accepted eacd composition, numerical kernels and Offline path are unchanged. This is a cold-context prerequisite and stopped-candidate interface; it does not retrofit an already running Main context.

`acquireCompleteAmbienceColdLease(context)` synchronously reserves `allowCold:true, wake:false` before any asynchronous preparation. Its first returned lease is the caller-owned context-session/bootstrap reference. It does not resume the context or create Source7a. The context must still be virgin, suspended and at time zero after host preparation. An independent resume race cleans the prepared owner and refuses the context. Running or advanced contexts without this prerequisite refuse before resource admission.

A candidate obtains a distinct `bootstrap.retain()` lease. Canceling or retiring that candidate releases only its reference; the context-session owner deliberately remains. There is no hidden keeper. Only the final explicit reference retires the shared bank and spatial owners. An unacknowledged final retirement retains blocked ownership and requires a fresh context. The same context cannot silently recreate a retired complete profile. The caller must acquire this prerequisite before the existing stopped-runtime bundle's synchronous `wake:true` reservation.

`selectCompleteAmbienceEnvironment(base, candidateLease)` returns a new frozen environment. The base object and original Native constructor/prototype are not changed. Its `ambienceFactory` creates a complete facade with an instance-local staged session; its `prepareAmbienceStart` belongs only to those facades. Unclean bed retirement rejects instead of resolving a generic success. `prepareContext(offline)` delegates to the original base environment; a new live context requires its own explicit cold prerequisite. No backend choice is stored in song data.

`buildCompleteAmbienceBundle({context, environment, settings, seed, offset})` constructs a stopped, prepared candidate with one private unity output. The output permits a later ordinary0-to0 edge publication through the existing detached bundle journal. Partial construction and cancellation attempt both facade retirement and private output cleanup. Component disposal is idempotent. The caller keeps its context-session reference throughout candidate cleanup.

## Prepared start and lazy constructor identity

`AmbienceStartStaging` prepares actual phase/walk resources for the known piece offset, original per-layer period factors and selected Brownian/Sine mode. It stages resources in the original loop-first, weather-callback order. It assigns no layer birth and creates no lazy layer. Forecast preparation performs bounded off-thread numerical work; it is not claimed to perform zero speculative RNG work. The active receiver's layer created mask, render frame, per-layer RNG counters and constructor map remain unchanged. First publication uses the ordinary lazy ensure path and its actual constructor epoch. An already created wave retains its captured offset and is never rebuilt for a later piece offset.

Unused superseded resources close their worker streams and await acknowledgement before a replacement is reserved. Cancellation retires unpublished stages; retirement waits an already publishing constructor before closing its stream. This preserves cross-port publication ownership. There are at most8 pending start preparations per session and at most6 unpublished layer recipes. Existing source and pool bounds remain unchanged.

`startPreparedAmbience(facade, {offset, requestedAt, leadSeconds:.5, signal, isCurrent})` awaits loop PCM, queued controls and required unborn constructor resources. It verifies settings are still current, then chooses `max(requestedAt, readyAt + .5)`. It invokes the ordinary facade start itself, once. Callers must not start again after this hook. A caller may retain a later authored timestamp; the half-second minimum lead is fixed for this profile. Actual source-preparation lateness remains a named failure with diagnostics; no onset is fitted away or recovered from the past. New settings or cancellation before booking retire the staged resources and preserve their acknowledgement result.

The preparation receipt includes resource plan, chosen/ready/requested epochs, captured offsets, actual constructor births and late frames. This is a startup transaction receipt, not an arbitrary mid-render snapshot. Runtime controls retain the accepted complete facade and its live bounded refill journal. Initial startup readiness does not imply that every future hot edit can meet an arbitrary low-latency deadline.
