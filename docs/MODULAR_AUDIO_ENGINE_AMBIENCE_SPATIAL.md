# Complete owned Ambience processing — isolated profile

This new standalone profile ports the original `Ambience.chain`, `applyShape`, `startLayer` gain handling, per-contribution fade operations, bed fade and `wanderLfo` processing. It does not change normal Ambience, its weather/loop preparation, application defaults or the previous immutable/pooled readers. Native filtered source-endpoint parity remains unaccepted in the earlier host slice; this profile does not manufacture browser silent flags from small PCM values.

The six layers retain their original order: rain, thunder, wind, waves, fire and vinyl. Each owns the distance lowpass, the two shelter lowpasses for the three weather layers, the four-gain stereo width matrix, native stereo panner, original level projection and its drift gain. The bed owns its independent fade followed by total drift. Source PCM enters through nineteen separately owned stereo contribution lanes, allowing the existing six-layer/weather/crossfade source budget without silently mixing independent fades first.

`OwnedAmbienceSpatial` captures a versioned JSON setup and chronological host commands. Every command includes the canonical frame where the host issued it and its original authored time in seconds. Time products and original seconds remain distinct in the attributed native AudioParam fork. The literal native constant/sample-accurate panner Float32 boundaries are separate. The sine uses exact source-defined one-harmonic Native FFT preparation (and immutable exact zero-phase resources), the original phase/seed/period recipes and native scheduled-start/interpolation clock. Brownian preparation preserves the original mulberry32 draws, clipped Box–Muller normal, fold and two-second linear knots; changing period changes future undrawn knots only. A first Brownian path at a large piece offset is prepared before rendering, not sought on an audio callback.

The processing caller supplies separate audio and parameter-pull masks for source contributions, layers and filters, plus unpulled/parameter-only/audio bed mode. Audio is a subset of parameter activity. Unpulled histories hold; parameter-only operations advance the corresponding AudioParam histories. This explicit executor contract is deliberately distinguishable from browser `IsSilent`, `PropagatesSilence` and deferred main-thread output-disable behavior. Source buffer onset/stop/cursor behavior remains the separately accepted reader's responsibility. The processing core owns contribution gain states, not a substitute buffer cursor.

Preparation bounds are six layers, nineteen nonzero-owner contributions, 4,096 chronological raw commands, 512 events per ordinary parameter lane, 256 per wander lane, integer sample rates 8–192 kHz, piece offsets up to 1,000,000 seconds, and an optional finite offline horizon up to 480 seconds. Ordinary finite-control lifetime admission refuses before mutating an existing command or source state; future live refill admission remains explicitly outside the accepted contract below. Bounded history exhaustion is explicit; this first isolated profile does not claim indefinite live refill or in-flight DSP snapshot serialization. JSON stores setup plus authored control history and reconstructs a fresh deterministic instance. Reset retains allocations and restores this captured chronology.

After preparation, canonical 128-frame rendering, owner cancellation and reset allocate/free/grow nothing in the private allocator build. Reset may perform preparation work; it is not a promise of callback-safe reset cost. No global mutable source state is shared between handles. Native graph fan-in can choose a different Float32 addition order; per-layer and full-bed comparisons are reported independently, and aggregate bit identity is not presumed.
