# Owned complete room convolution chain

This opt-in composition executes the actual RoomColour pre-delay/damping stage and static sampled convolution together in one Worker. It preserves the original full and Light topology. Existing native defaults, All routing, shared room ownership, wet/dry gains, IR selection/loading/crossfades and compressor boundaries are unchanged. There is no live AudioContext control-clock import in this slice.

## Complete captured contract

The version 1 profile is `owned-room-colour-convolution-source-local-v1`. Its strict seven fields capture version, profile, clock, routing, colour spec (fixed-channelv1, authored activityv2, or explicit null), convolution spec, and both complete published manifests. The clock is explicitly `captured-source-local-seconds`, origin frame0, quantum128, liveContextImport=false. Initial settings and ordered original control seconds roundtrip without frame rounding. The stream starts on a future AudioContext frame aligned to128, so its local canonical128 control grid has a declared origin. Arbitrary current-time UI messages are not silently converted into captured controls.

`OwnedRoomConvolver` constructs one independent RoomColour Wasm memory and one independent convolution Wasm memory. The modules are trusted immutable results of their existing SHA-verifying loaders. Both supplied complete identities must match the captured manifests; a cloned WebAssembly.Module is not independently re-hashed in a producer. Identity comparison ignores object-key ordering, preserves array ordering and includes the full source/runtime/host metadata rather than just a numeric Wasm tag. A wrong profile, rate, routing, source-channel count, supplied identity, clock or incomplete component rejects before processing.

Matching routing preserves genuine mono or stereo colour followed by the corresponding convolution input. Light routing is explicitly `chromium-ordered-speaker-stereo-to-mono-v1`: stereo RoomColour remains stereo, then is downmixed immediately before the mono convolver. Moving that average before colour would change native stereo control/filter behavior. The Rust downmix follows the pinned Chromium AudioBus two ordered Vsma operations: half-left to a zero destination, then fused half-right plus that destination. The original revision, audio_bus.cc hash and BSD notice remain in the convolver profile. Native comparisons are required; no generic browser bit identity is implied.

The new `convolver_render_stereo_to_mono` ABI uses the existing two fixed input buffers of a mono-input kernel. Both input planes and all render bounds are preflighted before mutation. It adds no adapter delay and makes no render allocations. Original `render` and both previous partition profiles retain their existing math. IRs remain complete; no normalization fit, truncation, clipping or extra limiter is added. Nonfinite output is terminal before any Worker PCM publication.

## Worker and transport ownership

`createConvolverStream(..., {room:{assets,spec,routing}})` explicitly enables composition. Omitting room retains the accepted no-colour path. Each Worker owns one complete composed state; it processes RoomColour, optional Rust downmix, then Rust convolution in that order. Source PCM and returned wet PCM travel on the existing direct Worker/AudioWorklet MessagePort, without a main-thread relay.

Light uses two physical source planes and one output plane. Buffer capacity is max(inputChannels,outputChannels), while the AudioWorklet output channel count stays exactly one. This avoids underallocating source buffers or silently duplicating the mono output. The fixed default transport delay remains approximately0.5s, rounded to128 frames; zero kernel delay, pool bounds, exact source-frame sequence, fail-on-gap behavior, generation checks, cancellation and acknowledged disposal remain declared by the long-convolver contract. Caller dry paths require matching delay/PDC before combining them with streamed wet output.

A composition stream snapshot has version2 and one complete composition authority; it does not duplicate a competing primitive spec. Captured IR/settings, source-local clock, both exact manifests and routing reconstruct a cold unit. The separate finite `renderRoomConvolverWorker` helper validates the same complete identities, makes tight owned transfers, preserves caller buffers, bounds output to4,194,304 frames, supports cancellation and terminates its Worker after completion/error. It verifies complete reset, irregular partition replay, independent units and saved fresh reconstruction. This is not a midstream FFT/filter/control-queue snapshot or a live-target scheduler.

## Verification and limits

Eleven direct composition tests cover six rates with genuine mono, full stereo and Light chains; exact irregular partition/reset replay; complete local-time and IR persistence; independent states; raw downmix equations/preflight; immutable captures; identity/routing/clock rejection; no-colour equality; and terminal overflow. Five actual Node-worker tests cover full/Light finite replay, both complete identities, direct stereo-to-mono stream packets, cancellation/bounds and caller mutation after dispatch. Existing transport/factory regressions additionally verify stereo input credit with mono output, partial tails, asynchronous ownership and cleanup.

`tools/auditRoomConvolver.mjs` instruments both real Rust allocators and reads their counters before disabling watches. Twelve cases run complete production3s full/2s Light tails at8/24/44.1/48/96/192kHz, then reset both kernels. Every watched span has zero allocation/reclamation calls and no memory growth; the largest combined observed Wasm memory is58,195,968bytes. Report: `reports/modular_audio/room-convolver-allocation.json`. JS copies, validation, message objects, snapshots and preparation are outside that zero-kernel-allocation claim.

The finite fixtures explicitly book a source-end layout event at ceil(sourceFrames/128)*128; this comes from the known source schedule, not output analysis. Speaker-mapped mono output then feeds the original full/Light convolution input law. Both processing stages continue in audio mode in these finite fixtures; general native silent-bus scheduling is not inferred.

The fixed `tools/room-convolver.html` native batch has15 cases: full stereo and post-colour Light at six rates, plus genuine mono at44.1/48/96kHz. It calls the actual original RoomColour methods against native nodes, schedules their captured seconds, uses original normalized sampled-room impulses, and compares complete output against the composed Rust Worker. The routed batch checks full and Light PCM at48/96/192kHz and two simultaneously independent rooms in one AudioContext, through a separate downstream capture worklet. Both absolute and relative-RMS limits are predeclared1e-4. Desktop browser acceptance passed all15native cases and all6routed cases, including two simultaneously independent full/Light rooms. Native maximum absolute error is4.470348358154297e-8 and maximum relative RMS2.443934528873854e-7, within both unchanged1e-4bounds. Every routed PCM comparison is exactly equal, with zero gaps/overruns/rejected packets and correct startup silence. Physical listening is not assessed.

Remaining integration boundaries are native decoding/resampling and IR loading policy, exact wet/dry target gains, shared-send ownership/summing, live control-time import/cancellation, IR switching/crossfades, caller PDC and default adoption. No All migration or callback-safe convolution claim follows from this executable Worker composition.
