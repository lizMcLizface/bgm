# Generator prepared Sweep join

This optional application profile composes the accepted Rust Sweep stage with the selected nine-control Generator master. The ordinary Generator/native Sweep path remains the default. Select it explicitly with prepareGeneratorRustMaster(g, {channels, prepareSweep: true}) while the actual shared AudioContext is suspended at time zero.

The stage is constructed cold and armed only after the role, scalar and output roots activate. Its existing constructor authors OPEN once. Actual arm receipts must show the unrendered native intrinsic defaults [350, 350, 1, 1], one admitted constructor command and zero filter DSP frames. There are no program edges and g.sweep remains undefined before the first actual filter move. This preparation policy is supported by the separate six-rate Prepared OPEN versus late Native construction evidence; that Offline comparison alone does not prove unsuspended live demand transitions.

On the first Generator.applySweep call, one private synchronous writer validates the complete values/tau and actual stage capacity before changing any edge. It then removes the direct post-fade-to-trim edge, connects the actual prepared input/output, publishes demand and authors the first target once. The Generator compatibility output identity stays unchanged. Later moves use the same privately owned stage. There is no additional OPEN command, fabricated source-frame advance, native allocation at first use, fallback or synchronous intrinsic getter.

The route certificate is held in private WeakMaps. It binds the exact Generator, retained clock object, output root, trim destination and actual stage endpoints/processor. A look-alike facade or public identity DTO cannot authorize the route. Output-root checks use the low-level certificate verifier without recursively invoking the root. The actual stage and its facade/endpoints are protected from source and runtime candidate reuse.

The stage retains its own Main clock lease and an actual output-root borrow. Source-slot edits and full runtime successors retain the stable Sweep cell rather than replacing or disposing the stage. Retirement first starts the actual stage disposer synchronously, so its terminal-gate write precedes any additional program-edge cuts, including parent-originated isolation. Uncertain gate authorship retains those extra edges until the actual typed Source receipt or context close. Retirement then closes only the captured program edges and awaits the real stage disposal promise and typed clean Source receipt before restoring the direct route and releasing dependencies. Starting retirement is not release proof. Parent quarantine follows the same gate/ACK boundary, and gate/Native isolation failures remain sticky. Program isolation does not author a demand-zero transition or remove the actor's private keepalive before its terminal receipt. Partial publication is sticky and isolated; uncertain retirement keeps dependencies until actual context close.
