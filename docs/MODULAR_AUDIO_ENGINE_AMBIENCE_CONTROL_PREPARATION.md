# Owned Ambience control preparation

This standalone offthread producer prepares the original drift resources for a future live Ambience executor. It does not change the default backend or the accepted finite processing kernel. Public identity `64f5ce456738d611` contains40,756 bytes of Wasm.

The Brownian planner reuses the unchanged owned `Walk` port of the original `WalkPath`: seeded draws, value-at-offset catch-up, two-second knot lattice and period-at-booking order are preserved. Preparation works on copied fixed-size state. A first resource includes the nominal90-second forecast and one guard knot; publication uses the actual constructor clock and the original left-associated `birth +index*2 -offset` expression to choose its exact prefix. The acknowledged prefix alone advances committed RNG state. Subsequent resources carry consecutive index/value pairs, with at most256 points each. They retain the acknowledged birth rather than pre-rounding relative event clocks. Large overdue requests refuse before drawing or changing committed state.

The phase resource owns original layer phase, piece offset and actual constructor-period arithmetic, then invokes the accepted pinned Native AVX/FMA preparation helper. It generates tables from coefficients and algorithms rather than stored output datasets. Phase generation and large-offset random seeking are explicitly preparation work, never callback work. Rates are bounded to integral8,000–192,000Hz, periods15–900seconds and offsets0–1,000,000seconds. Phase tables have2,048/4,096/16,384 samples according to the original rate profile. This is the existing pinned Native architecture profile, not an architecture-independent promise about every browser FFT.

`OwnedAmbienceControlPreparation` offers `first(periodAfter)`, `refill(now)`, `commit(id,count,birth)`, `cancel(id)`, `setPeriod(value)`, `stats()`, `reset()`, `save()` and `load()`. Only one resource may be pending. Period changes require its acknowledgement or cancellation. Packets contain copied Float64 index/value arrays; changing a caller's packet cannot change owned state. Wrong tags, wrong prefix counts, unsupported recipes and capacity overflow refuse without replacing committed state. Reset retains monotonically increasing runtime acknowledgement tags. Tags belong to a worker session; the future host must also fence lease/generation identity across reconstructed sessions.

JSON saves contain the immutable recipe and a bounded journal of committed preparation operations, capped at4,096 entries and2MiB. Pending resources must be committed or canceled before saving. Reconstruction reproduces future points and RNG state; it is not a serialized audio/IIR state or an in-flight port snapshot. Histories deliberately refuse once full, rather than silently discard operations needed for replay.

Permanent verification covers24 first bookings and960 rolling refills at six rates, offsets0/17.3/89.25/1,000,000, period changes and8,277 exact Float64 points against the unchanged original JS class. Initial values, draw counts and next indices match exactly. Independent JSON replay, canceled forecasts, malformed acknowledgements, caller packet mutation, reset, resource bounds and invalid save cleanup pass. All21 nonzero-phase Native recipe hashes match bit for bit, including original Rust recipe arithmetic before FFT. The allocator audit reports zero allocations, frees or memory growth after planner creation during first booking,79 refills, overdue refusal and reset. Cold phase preparation allocates its table/workspace separately.
