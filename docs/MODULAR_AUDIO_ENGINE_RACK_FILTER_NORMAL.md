## Owned primitive and limits

synth-engine/rack-filter-normal imports the accepted Biquad coefficient/sample and TailFrame helpers read-only. Seven independent256event timelines retain original Float32 targets, f64 authored seconds,20ms native smoothing and the retained predecessor rules. A separate local timeline fork uses literal native f64 past-convergence and f32 ProcessSetTarget convergence constants. Main type is an immediate observed property operation, not a smoothed AudioParam. A type change clears only the main filter's history. Fixed cut Q and original clampHz recipes are retained.

The direct primitive accepts integer8k..192k, canonical128frame calls up to2^40-128, two input planes and explicit five-bit audio/parameter/stereo masks. Audio must be a subset of parameter pulls. Each stage owns its histories, current layout, cached coefficients and cached tail time. Declared layout changes recreate only that stage's kernels; parameter-only/unpulled calls neither execute DSP nor clear denormal histories. Silence is never inferred from PCM. Unknown flags must be supplied by an authority or refused. Generic native mainthread tail scheduling is not emulated by a made-up constant.

OwnedNormalFilter supports explicit activity, cold native reset, immutable spec JSON and a bounded cold replay DTO containing every observed/authored command and activity state (4096of each, up to one hour). Source PCM/recipe is separate caller-owned material. This is deterministic replay from a cold state, not an in-flight heap snapshot. Every render/update/reset uses preallocated Wasm state.

## Normal host admission

The NEW host initially supports44100/48000/96000/192000Hz only and requires one explicit authority. Unsupported8k/24k and unknown native activity are typed refusals before node creation; there is no hidden native fallback.

continuous-program is a caller guarantee that a pulled program bus is natively active, including active AudioWorklet zero outputs. It is not inferred from nonempty arrays or numerical samples. Upstream gain0, arbitrary native source-ended/tail flags and finite source-lease preview transitions are outside that authority. They require an explicit activity plan or refusal. The original four outer gains retain input gain1 and original bypass; bypass does not freeze DSP. Output-edge demand is independent from the activity authority.

explicit-activity uses a bounded immutable canonical per-stage future plan, prepared before processing. It is not a mutable single-parameter flag whose publication could arrive late without an authored-frame proof. Edits require a new offroute owner. Physical input/output layouts are checked against the declared state; mismatches fail closed instead of dropping a stereo tail or guessing a flag. The normal worklet retains dynamic mono/stereo output. Standalone owned Graph/worker callers can drive the direct explicit masks without these Web Audio output-layout restrictions.

The original JS setter order is preserved: cuts mode makes four frequency setters, immediate main.type, then main.gain; other modes make four cut setters, immediate main.type, then main frequency/Q/gain. Thus there are5or7 actual currentTime reads and6or8 lossless command records. The type property reuses its preceding setter's authored clock and applies when observed; it does not introduce an extra fake native time read. Thirty-two acknowledged stamped records preserve complete contiguous publication. There is no native evaluated-value or coefficient bridge.

The separate new whole-extra facade preserves the original input/output/through/wet gains. Running prepareInitial uses a temporary zero-gain control sink with DSP demand false, and temporarily disconnects only input-to-owned-DSP so an already begun program cursor cannot advance. It detaches the quiet sink before restoring that input edge, and retains the last declared program layout while pumping controls. This prevents a control-only empty physical bus from resetting stereo histories. Suspended/offline preparation prebooks without waiting for a processor callback. Cleanup awaits both processor ACK and pending preparation-finally cleanup.
