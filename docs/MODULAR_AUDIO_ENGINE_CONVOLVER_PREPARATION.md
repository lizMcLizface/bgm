# Original room impulse preparation

This independent preparation slice preserves real remaining Convolver callers. It changes no defaults, existing routes, Graph code or accepted static convolver ABI/spec/327,680-frame limit. Preparation belongs outside audio callbacks; no zero-allocation or callback deadline is claimed for whole-IR generation and transforms.

The audited production callers are:

| Caller | Original IR and processing | Native normalization |
| --- | --- | --- |
| nodes/reverb.js and sharedReverb.js | Native-decoded six FLAC rooms; remaining-energy trim, 3s full/2s light cap, optional mono reduction, quantized decay; RoomColour remains external | true |
| iowaModel/player.js | Full untrimmed reverb4.flac decoded at context rate; mono voice input, stereo IR | true |
| synths/piano/player.js | Original fixed-seed stereo 2.4s decaying-noise room | true |
| stringModel/realtime.js | Measured mono body/wake IR | false; already covered by accepted static convolver |

All six source FLACs are stereo 44,100Hz. The full Iowa reverb4 has 433,088 source frames, 9.82059s. Native decodeAudioData and its resampling remain an explicit host capture boundary; Rust consumes those captured same-rate Float32 channels. The unused roomModel.js procedural-room helper is not substituted for these actual sampled assets.

The version1 specification is complete and strict: kind decoded-room or piano-room; integer sampleRate8,000–192,000; matching irSampleRate; trim none/full/light; optional decay0.3–120s; explicit normalize boolean; one/two equal channels for decoded input or null for the fixed piano generator. Maximum decoded input is2,097,152 frames per channel. Unknown fields, numeric coercion, unsupported channels/rates and nonfinite samples reject. Outputs are detached owned Float32 copies; temporary Rust handles are released after every request.

Original transforms preserve their order: trim first, optional light mono average, then decay. The trim scans f64 energy by the original iteration order, cuts below remaining-energy -60dB, uses a50ms end fade, caps full/light at3/2s with the original0.8s fade, and preserves the original near-end no-copy policy as metadata. Decay first compares the raw value with buffer duration, then uses its rounded tenth for k=-6.91/(decay*rate). That ordering matters when2.36s rounds to a2.4s buffer duration. The piano generator retains2.4s, seeds1234+77*channel, original LCG, evolving one-pole coefficient, power3.2 envelope and4ms attack.

Normalization retains Chromium's minimum RMS0.000125, -58dB calibration, Float32 target arithmetic and44,100/rate scaling. The explicit portable profile uses logically aligned eight-lane f32 squared-energy accumulation, following pinned Chromium AVX reduction. Native CPU alignment, architecture and FFT-coefficient scaling can differ; this profile emits scaled time-domain Float32 IR and requires actual native output acceptance at the predeclared1e-4 absolute/relative-RMS bounds. It is not a claim that every browser has bit-identical reduction. Source URLs, hashes and notices are retained in the new crate's CHROMIUM_PROFILE.json and CHROMIUM_NOTICES.txt.

Twenty-two permanent tests pass: actual private PianoPlayer generation at six rates; actual exported trimImpulse/monoImpulse/decayedImpulse at six rates and all three trim modes; raw-versus-quantized decay edge; f32 normalization/guard at six rates; complete saved input/reload; independent returned buffers; strict host/raw lifecycle and resource bounds. The focused audit report additionally records the maximum decoded input and exact source-reference differences. These checks are separate from native FFT-scale parity.

preparedRoomToConvolverSpec uses the already accepted normalize=false kernel only when the complete prepared result fits327,680 frames. It never silently crops an impulse. Full3s at192k gives576,000 frames; piano192k gives460,800; full Iowa rooms exceed the limit even near44.1k. Those prepared resources remain complete and adoption rejects explicitly. Longer execution is a future separately reviewed resource/composition step. Light mode requires an explicit mono input boundary; native-equivalent stereo downmix, RoomColour predelay/Biquad, wet/dry law, shared buses, asynchronous loading and live IR crossfades remain host responsibilities.

The fixed tools/convolver-preparation.html batch uses the actual private piano generator at six rates, native-decoded original FLAC assets, light/full transforms and oversized Iowa/high-rate cases.
