# Full room convolution execution

This opt-in continuation closes the old execution-size boundary for the original Iowa and piano room impulses. It does not change All defaults, native decoding, source engines, RoomColour, native compressors, wet/dry routing, or the accepted version 1 impulse contract. Native FLAC decoding/resampling and original coefficient preparation remain explicit boundaries.

## Explicit profiles and bounded schedule

Version 1 remains `static-f64-nonuniform-128-8192-v1`, maximum 327,680 IR frames. Its original full-spectrum algorithm and raw `convolver_new` entry remain unchanged. Six-rate comparisons against the previously published Wasm produce exactly equal PCM; historical browser reports keep their original build identity.

The new complete version 2 spec adds the required `profile: "static-f64-half-spectrum-nonuniform-128-65536-v2"`. It explicitly selects `convolver_new_long`. Both profiles use same-rate Float32 inputs/IRs, one/two input and IR channels, normalize=false, explicit mono/stereo diagonal routing, no truncation and zero kernel adapter delay. The long hard cap is 2,097,152 frames per IR channel: about 10.92 seconds at 192 kHz, covering the complete original 9.82059-second Iowa room after host decoding and the original 2.4-second piano room. Version 1 still rejects an oversized resource.

The long algorithm retains the direct 128-tap head, then one nonuniform stage at each power of two from 128 through 32,768. The remaining tail starts at 65,536 and uses a bounded frequency-delay line of at most 31 partitions. There are at most ten groups and a 131,072-point FFT. Each group publishes its cached block exactly when its IR offset becomes due. Only bins 0 through N/2 are stored for H and X; the inverse reconstructs the Hermitian half. This changes the execution schedule and spectrum storage rather than merely increasing a length constant. Plans, spectra, history, input/output storage and overlaps are owned and prepared before rendering. No coefficients are cropped, fitted, post-normalized or zeroed to satisfy comparisons.

## Worker transport

`createConvolverStream(context, assets, spec, options)` is an isolated asynchronous factory. It loads the import-free published transport worklet, prepares one private Rust kernel in a dedicated Worker, then transfers one MessageChannel between them. PCM never relays through the main thread. The factory returns one caller-connected input/output AudioWorkletNode, `start({startFrame,frames})`, `completed`, `stats`, `check`, `snapshot` and idempotent `dispose`; optional AbortSignal also cancels pending startup. Failed module registration can retry. Caller configuration is captured before asynchronous startup.

Each input/output packet owns one fixed planar Float32 buffer. Default blocks are 2,048 frames; the configurable fixed transport delay is 0.125-2 seconds, default 0.5 seconds, rounded to 128 frames and never below two blocks. The pool is exactly ceil(delay/block)+4 buffers, hard capped at 192. No additional PCM credits are created while processing. Credits return only after their scheduled output block has been consumed. Source-local packet frames are contiguous; generation, length, ownership shape, sequence, capacity and finite PCM are validated. Both producers also reject nonfinite Float32 output before publishing PCM: even finite inputs and coefficients can overflow. This is a terminal error, with no clipping or coefficient change. Gaps, exhausted input credit, malformed/duplicated/late return packets or producer failures stop the stream with an error and observable counters. The transport does not silently shift time, discard gaps or claim seamless recovery.

The start clock is an explicit future absolute AudioContext frame aligned to 128. Packet clocks begin at source frame zero; output begins exactly latencyFrames later. A finite frame budget includes the caller's desired complete IR tail; disconnected input contributes zero samples. The kernel itself still has zero latency. A caller combining immediate dry and streamed wet paths must delay/align dry by this declared transport latency. This helper does not perform app-wide PDC or modify Iowa's existing room bus automatically.

Each factory owns one worker and kernel. Two maximum-sized stereo kernels are verified together in a Wasm instance, but deployment concurrency is not unlimited: their observed combined Wasm memory is 328,990,720 bytes, exceeding 256 MiB, before JS specs/transfer/capture memory. A single maximum stereo kernel accounts 163,594,848 owned buffer bytes (under the declared 192 MiB per-kernel bound); the one-worker throughput run observes 165,281,792 Wasm bytes. These are tested desktop resource bounds, not a phone memory guarantee. Whole-IR preparation, JS capture, transfer messages and control objects are outside the zero-allocation Rust render claim.

## Verified functional and timing evidence

Fourteen long-profile permanent tests plus the original seventeen kernel tests pass. They cover six-rate exact legacy replay, independent sparse convolution through every maximum-sized tail partition for all four channel maps, exact impulse positions through frame 2,097,151, complete IR persistence, irregular render partitions, independent handles, cold reconstruction, reset and raw contract rejection. Two additional actual Node-worker tests render beyond the previous finite 1,048,576-frame cap and verify complete long-profile lifecycle replay. Nine transport/worker tests and four factory tests cover actual direct ports and buffer detachment, source-local origins, exact delayed PCM, a partial final block, bounded buffer reuse, startup cancellation, registration retry, gap failure, malformed/stale/duplicated packets, overflow rejection, spontaneous processor failure and acknowledged disposal with a bounded one-second fallback. The finite worker has a third dedicated overflow regression.

`tools/auditLongConvolver.mjs` records four maximum-IR channel-map cases, each with two concurrent handles, a complete history ring plus tail, reset and independent clocks. Every watched render/reset span has zero allocation/reclamation calls and no Wasm memory growth. Report: `reports/modular_audio/convolver-long-allocation.json`.

`tools/auditLongConvolverThroughput.mjs` measures eight actual Node-worker cases after warming the complete spectral history, followed by three seconds of dense-source processing. The actual Iowa-duration cases at 48/96/192 kHz have offline elapsed/source-duration factors 0.07191/0.13730/0.28970 and maximum copy-plus-render calls 22.7044/24.8192/33.2603 ms. The maximum-size stereo case at 192 kHz reaches factor 0.35367 and a 37.4482 ms maximum call. The complete matrix remains finite with exact frame accounting and no memory growth. Report: `reports/modular_audio/convolver-long-worker-throughput.json`.

Those timings include preemption and finite monitoring and do not establish AudioWorklet callback deadlines, a universal safe buffer size, browser transport behavior, full-song CPU headroom, background/phone behavior or device output quality. Execution remains worker-only; no serial callback promotion is inferred.

The fixed `tools/convolver-long.html` page has eleven silent native full-IR comparisons and a separate actual routed Worker/AudioWorklet batch at 48/96/192 kHz. Native cases use full original Iowa rooms, original normalized piano/trimmed rooms and all four channel maps. Streaming captures PCM in a separate downstream worklet after the real output connection, checks exact startup silence and declared delay, and requires zero gaps/overruns/rejected packets through the whole tail. Absolute and relative-RMS limits are both predeclared 1e-4. The accepted desktop results for this kernel/host pair are recorded below; physical listening is not assessed.

Persistence is complete captured static IR plus original spec/profile and stream settings. It deterministically reconstructs a cold kernel. It is not a midstream FFT/history, source-note or pending-port snapshot. No normal source/default migration should be inferred from this isolated executable boundary.
