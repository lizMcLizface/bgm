# Stopped Generator runtime candidates

This unselected transaction prepares and cancels an actual detached owner bundle while preserving the existing Generator, Transport, role containers, plan and listener Sets. It does not replace a Generator, copy a second Generator's fields, change normal UI selection, or certify a complete all-Rust path. A separate Main-only binding now has a desktop publication/successor/rollback proof; its exact admitted scope is recorded in MODULAR_AUDIO_ENGINE_MAIN_STOPPED_RUNTIME.md. Normal UI selection and complete Ambience start remain separate integration steps.

`captureStoppedRuntime` captures every existing role, including external presets and percussion, full settings/presets, runtime revisions and exact owner/control-node identities. Activity, held notes, source-input leases, future percussion bookings, queued voices, pending source/engine/percussion/shared-rack work and unhealthy owners are refused. Settings, presets and pointers are rechecked after asynchronous work and before publication. Returned inspection data is copied; it cannot rewrite the saved authority.

`prepareStoppedRuntimeBundle` reserves synchronously before its first await and explicitly wakes Native before Source7a preparation. Environment preparation and clock binding each require an explicit `{context, value, release}` upstream lease. Cancellation waits even for late preparation and its release acknowledgement; no value.dispose or cached global-clock ownership is inferred. A running future-epoch Source7a with an already-valid anchor is required. A cached cold-zero authority is refused even if its context has since resumed.

The candidate owns all six selected instruments, six role Wander owners, Ambience and private shared/section return nodes. Sources retain their presets, polyphony and backend selection. No unpublished return joins the installed mix, shared reverb hub or global return destination. Source/control owners are registered before readiness or routing can fail. An installed owner cannot be returned as a new candidate; duplicate ownership without an explicit shared lease is refused. Cleanup attempts every resource and retains bounded attempted/closed/error/receipt health. Explicit negative, unreleased or quarantined receipts cannot count as success.

The first profile refuses global native shared-room hubs, existing Wasm room pools and active room routes before allocation. It also refuses direct/legacy physical Instrument constructor paths whose partial-construction cleanup is not owned; it never substitutes another sound or drops that role. Complete Ambience's first arena is cold-only: a running Main context without a separately owned cold prerequisite is not silently given a fallback. Native/Offline and existing preferences are unchanged.

While the builder still owns the explicit program-input-absent phase, it temporarily demands only the newly created Wander output and writes literal zero to its own destination. The original settings call and returned epoch/frame remain unchanged. It waits until that queued control is applied, disconnects the exact temporary edge, and obtains its own typed release receipt before exposing the bundle. It never connects an instrument source, mutes an existing input, synthesizes an epoch, rebases a knot or restores DSP history. Nonzero input contradicts the declared isolation and is rejected; zero samples are not used to infer authority.

The exact Native-edge journal admits at most96 edges and validates every same-context endpoint before its first mutation. An application failure reverses only completed exact edges. The future Generator-owned binding must provide synchronous preflight/publication/restore and captured previous-owner retirement; asynchronous publication is refused. Previous-owner retirement has its own reservation through ACK. Failed pointer/edge rollback retains a visible quarantine and must not permit normal playback as if installation succeeded.

A separate guard exists before child construction. If a constructor rejects before returning a bundle and reports failed partial cleanup, the guard waits for that child task and retains the reservation. It cannot release idle simply because there was no returned owner. It also covers cancellation before the child callback starts without waiting on its parent retirement fence. Late success cannot erase the original cleanup failure.
