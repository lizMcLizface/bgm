# Live Ambience session candidate

This new leaf is `src/modular-audio/ambienceSpatialSession.js`. It is not selected by the normal app environment. It uses the accepted context-owned live processor and additive captured-wave recipe/intrinsic snapshot API. Existing Ambience, source preparation, offline rendering and backend defaults are unchanged.

`createAmbienceSpatialSession(pool,{offset,wander,birth?})` acquires one prepared bed, prepares the original total Brownian constructor at period180, then applies requested settings. `start(at,offset)` changes the piece offset used by subsequent lazy constructors. `ensureLayer(layer,{shape,birth?})` captures its then-current offset, period and mode and publishes offthread resources before admitting a source. A supplied birth retains authored seconds; an omitted birth is the actual publication-side context time after preparation. No timestamp is silently clamped and no context is resumed or suspended. Callers must await readiness and bookings before source playback. Preparation latency does not recover a past onset.

Control bookings execute in original call order through a bounded64-entry FIFO; receipt history is limited to4096. Six layers and nineteen contributions remain the kernel limits. Fixed weather ports0/1/2 map to rain/thunder/waves. Ports3..18 provide sixteen independent loop contributions. Admission refuses an occupied/full slot before connecting or replacing a source. `attachSource` owns one recorded node-to-bridge/output/input edge and leaves other outgoing edges intact. `cancelSource` detaches that edge, awaits kernel cancellation and updates typed demand before the logical slot is reusable. A session releases only its lease; the context pool and independent beds survive. Source PCM start/stop and cursor lifetime remain with the supplied source facade.

`setShape`, `setWander`, `resetLayerLevel`, `fadeSource`, `start` and `stop` forward original operation semantics rather than invented AudioParam objects. The layer reset uses the kernel compound operation: retain current intrinsic, cancel future level commands, book current/zero and the original shape target in one receiver execution. Switching an initially sine layer to Brownian prepares its real first stream offthread. Existing Brownian streams survive later mode changes; period edits affect future undrawn knots.

Demand is explicit; the candidate does not infer it from PCM amplitude. Its current composition scope is continuously active connected sources. Canceling the last layer source still needs a declared filter-tail demand policy and actual endpoint verification before normal adoption. A bank-source facade also does not necessarily implement Native selective disconnect: the existing bank wrapper removes all its edges and automatically frees its cursor on end. Normal composition therefore needs a dedicated bridge and appropriate cursor-retirement fencing, rather than passing arbitrary facades as if they were Native nodes.

`refill()` explicitly tops up all created Brownian streams. Its caller must preserve the original15-second scheduling policy and run before the retained90-second horizon. No automatic timer or Native fallback is hidden here. A request exceeding the existing256-point resource bound fails explicitly. Automatic scheduler ownership, source endpoint policy, configuration replay at a fresh common epoch and normal live/offline app integration remain pending. `describe()` is a diagnostic recipe/receipt description, not a mid-render DSP snapshot or replay API.

Nine permanent tests import the actual host, real-Wasm worker/receiver and strict Native-edge VM fixture. They cover FIFO lazy offsets; sixteen-loop admission and ACK-before-reuse; independent beds and unrelated edges; pre-mutation invalid requests; actual connect rollback; compound reset/first-walk activation; known caller detachment and repeated disposal; retained unexpected cleanup failure with quarantine; and real hot-upload cancellation during disposal with all pending request maps cleared and the independent lease unchanged. The focused live/session suite has65 checks; unchanged finite16 cases bring the combined total to81. These tests do not by themselves claim actual browser acceptance or normal app adoption.
