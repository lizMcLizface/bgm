# Main explicit prepared-parts startup

This optional Main profile extends the stopped-runtime binding with Generator-owned preparation/publication delegates and one explicit complete-Ambience owner. It preserves the existing Generator, Transport, settings/listeners and Native tone/volume/duck/master controls. No application default or general UI engine chooser is selected. Core/FM source sample-onset parity is a separate boundary: the current source adapter still uses its existing host clock, even though the shared start uses the same authored API timestamp.

`Generator.prepareStoppedRuntime(options)` enters the existing synchronous wake reservation before its first await. Complete Ambience additionally requires the caller's explicit virgin-context bootstrap before this wake; the candidate retains a separate cold lease and never releases the bootstrap on cancellation. A running context without that prerequisite is refused. The running Source7a authority must pass the existing future-epoch/anchor checks. `commitStoppedRuntime(candidate)` validates the exact Generator, publishes/registers its explicit scope, and keeps readiness pending through captured old-owner retirement. An old-retirement failure retains the published candidate and persistent error; it never pretends the old runtime returned.

The complete owner is tracked once. Its separate `output` is connected to the candidate's private Ambience return. The facade is not given a synthetic Native `output` or synchronous `start` method. Successors require the actual complete stopped-status/drain receipt and retain the explicit owner/output authority for exact detach and retirement.

`startSelectedParts({music,ambience})` creates one bounded startup ticket. Music prepares without mutating the Transport. Complete Ambience prepares its real resources, chooses the future receipt timestamp, and starts once. The music token commits the Transport at that same timestamp, after checking settings, plan, source identities and current publication again. The optional `Transport.start(fromBeat,when)` preserves the original default timing when `when` is omitted. A missed deadline, stale ticket, changed settings or cancelled admission rejects; no source epoch is rebased and no rendered phase is fabricated. Main Play uses this branch only for the explicit published prepared owner. Native/default Play retains its previous path.

Stop cancels pending start tickets immediately, stops already-running music, and awaits complete Ambience's real source-ended, spatial cancel, cursor free and weather ACK observations. A cancelled uncommitted music start does not advance the resume bar. Startup primary errors and cleanup failures are both retained. A partial music commit is stopped explicitly. Complete stop uncertainty remains a failure even if later receipts arrive; there is no timeout-as-success.

The first profile has explicit edit limits. Source engine/family swaps, preset replacement/queued preset selection, and creation of the separate MIDI source are refused before source revisions, lists, owners or settings are changed. Same-owner parameter knobs remain available when their runtime family stays unchanged. New shared-bus, section-space and master-sweep ownership is refused before lazy construction. Automatic sequencer/arc/space policies requiring an uncaptured return are also refused before playback or settings mutation, rather than throwing for the first time from a later beat callback. Existing captured returns may be controlled without publishing a new owner. These guards have code `MAIN_RUNTIME_EDIT_UNSUPPORTED`; stopped reconstruction is required. A later owner-adoption registry or pre-owned placeholder policy is outside this checkpoint.

Prepared Ambience fades are limited to five seconds. Longer fades and undoing an in-progress authored source stop are refused before gain/settings/source mutation. Startup cancellation remains supported; undoing played/fading history is not represented as cancellation. SleepTimer registers its existing policy and preflights new selections so an unsupported automatic long fade is refused before prepared startup. Native/default fade behavior and Recorder duration controls retain their original semantics. Complete stop's explicit uncertainty budget is measured after the known fade endpoint plus its ACK budget; it is not a playback-usability claim.

The focused implementation checks pass 141 cases across 16 files, plus all 172 original Generator regressions (313 total). They cover cold/Generator authority, synchronous reservation, cancellation, future epoch/late refusal, primary plus cleanup errors, published-scope retention, fixed-owner edit refusals, long-fade policy, exact old Native paths and control routing. Both changed JSX files compile for ES2020.

The actual 48k desktop group passed with no unexpected errors. The first publication shared authored epoch 12.041333333333334 seconds between the actual prepared Ambience receipt and Transport beat; the successor shared 26.652 seconds. Both actual receipts had lateFrames zero, and every loop booking retained its requested frame. Music peaks were 0.21641805768013 and 0.22665467858314514; Ambience peaks were 0.07347330451011658 and 0.0734797865152359. All six separately routed layer outputs were finite/nonzero in each scene: first-scene peaks ranged from 0.014738239347934723 to 0.06891927123069763, and successor peaks from 0.014354486018419266 to 0.06892389059066772.

Each stop reported three actually retired loop sources with source-ended observation, spatial cancellation and cursor-free ACKs, plus one clean acknowledged weather retirement. The cancelled startup retained zero attached layers/sources, stopped status and no pending jobs; its uncommitted music resume bar did not advance. The successful successor closed the first published scope with no pending/unreleased resources. The forced third connection failure retained its original error, closed all 16 candidate resources without rollback quarantine, preserved the current owner/settings/Native controls and produced a surviving music peak of 0.0620512813329697. Generator, Transport, role-container, settings/listener and Native tone/gain/duck identities stayed unchanged. Terminal cleanup released the two explicit environment and clock leases, dropped the candidate/bootstrap refs to zero, and left tickets/shared arrays empty and idleBlocked false.
