# Normal live piano source ownership

Status: explicit opt-in normal `Instrument` source; 41 actual native desktop source/body/live cases pass. Normal mixed-host adoption is a separate pending gate. Existing finite piano/Graph implementation and the normal native default are unchanged.

## Runtime contract

`new Instrument({context, preset, polyphony, sourceBackend: 'owned-rust', voiceCompressorFactory})` selects this source for a real piano preset. `isOwnedPianoPreset(preset)` from `src/app/engine/pianoLiveSource.js` checks the exact existing `stringModel === 'piano'` boundary. The backend is an executor option, never a saved song or patch field. Other source families must use their matching controller; this controller rejects a non-piano note plan rather than changing its sound.

Await `sourceReady` before booking. After cold scheduled bookings, await `awaitPendingSourceBookings()` before offline finalization; this bounded barrier includes preparation and recursive actual booking, propagates preparation failures, and retains cancellation epoch guards. Parallel preparation keeps a bounded FIFO of original call reservations; actual physical-slot allocation and bookings commit in call order even when preparation completes in reverse. Cached notes also wait behind earlier cold reservations. It composes source/module/preparation readiness with optional managed effect readiness, without waiting for an audio callback on a suspended context. Existing `scheduleNote`, `startNote`, `stopNote`, `silence`, wake/sleep and stale held-note guards remain the host contract. Offline callers book notes and then call `prepareOffline()` before `startRendering()`; this transfers the complete prepared action stream in processor options. Real contexts use the source node's direct MessagePort. `sourceStatus()` exposes the owned version, preparation cache, failure and latest queried statistics. Disposing terminates preparation workers and explicitly frees the processor kernel; the following callback returns false.

The optional `voiceCompressorFactory(context, {hostLifetime:'instrument'})` hook preserves the native factory when absent. Managed stages remain connected while bypassed and own their dry/held-state policy. Their promises join `effectsReady`; no persistent backend configuration or instrument selector is introduced.

## Preserved source boundary

Original `Instrument` allocation, note expression, tuning, per-slot physical identity, scheduled and held note construction remain host orchestration. Preparation uses the existing actual piano worker with a forced Rust renderer and rejects any alternate renderer. Modal, acoustic and measured preparation retain the accepted algorithms and existing cache quantization. The controller owns its workers and cache; another instrument cannot invalidate its resources.

The new portable `synth-engine/piano-live` kernel owns strike/body playback, fractional buffer onsets, k-rate source detune, physical-slot mutable gain/filter automation, live release and stealing, gain 2.5, volume 0.2 and the original seeded BreathFormants air branch. Piano tonal sources bypass the formant input in the original path; only the independent air branch receives its normalizer and high/low filtering. Source output enters the same existing `synthMix` and common effect rack. Owned slots do not connect their native oscillator/BufferSource path to that mix. Shared instrument compression, room and later effects remain separate adoption boundaries.

This deliberately uses mutable timelines per physical slot, rather than reusing immutable finite note envelopes: real held-note release and source stealing edit the shared AudioParams of a slot. Current gain comes from Rust's rendered Float32 history. No native AudioParam is pulled to tell Rust the release level.

## Native clock evidence

The minimal permanent timing fixture contains original native desktop observations, not a second reference implementation:

- Nine actual gain probe runs at 44.1, 48 and 96 kHz measured three envelope shapes across five barriers. All 45 observed `AudioParam.value` values exactly matched the preceding rendered Float32 sample.
- Twenty-one actual AudioBufferSource onset runs cover three rates and fractional/nonaligned starts. Source frame conversion uses the native 1/1024-frame rounding before ceil; a fractional onset begins at the compensating fractional buffer position.
- The earlier accepted 16-case native detune probe established a partial first quantum at intrinsic zero and target decay beginning at the first full quantum after the onset. Aligned sources start with the target immediately.

Pinned Chromium source attribution and hashes live in `CHROMIUM_PROFILE.json` and `CHROMIUM_NOTICES.txt`. New all-mode filtering uses the actual DF1 algorithm with Float32 feedback and quantum denormal flushing. Existing accepted finite piano filtering was not modified.
