# Continuous worker Freeze

This NEW opt-in profile moves the existing original Freeze Rust kernel into a dedicated Worker. It does not duplicate or modify the accepted voice-FX kernel, select a normal effect backend, reproduce an earlier unseeded performance, or certify cross-role plugin delay compensation (PDC).

The original four-second capture copies and scans its recording window synchronously. Earlier measurements reach approximately10 ms at192 kHz, exceeding a128-frame audio period. The new AudioWorklet performs bounded transport only; the original scan, cloud selection, fades, grain mixing and RNG run in the Worker. No direct-worklet capture deadline claim is made.

## Authoring boundary

An explicit nonzero32-bit seed belongs to each actual owner. The existing xorshift32-v1 contract preserves the original grain draw order under that stream; Native Math.random defaults remain unchanged. A stage records continuously from arm(). It is not a drop-in claim for the original wrapper's lazy first-positive-mix birth or bypass pull policy.

The entire output, including dry sound at mix0, has one immutable delay L=ceil(rate*0.5/128)*128 frames. managedBypass:true prevents that latency disappearing when mix changes. There is no Native dry preparation fallback. Creation remains unarmed until actual Worker preparation, transport construction and cold credit installation are acknowledged. The factory requires a caller-owned latency registration bound to this context, actual owner and exactL before mutation. That registration is a caller contract; this leaf explicitly reports crossRolePdcCertified:false. Parent must provide real uniform role alignment/PDC and lazy-demand policy before production selection. Offline use is refused by this live profile; accepted standalone frozen rendering remains separate.

Controls reach the same transport receiver as source PCM. They are stamped at its next actual128-frame callback and travel before that callback's samples, in FIFO order. Each1024-frame packet still executes eight separate original render(128) calls, preserving callback-dependent retries. No raw AudioWorklet currentFrame, guessed epoch, silence detection, missing-frame catchup, output fitting or late packet recovery is used. A suspension/interruption retires this generation.

## Bounded resources and lifetime

One recyclable stereo pool moves input→Worker→delayed output→free, with at most192 credits. At most two completed output packets are in flight; the receiver installs at most one per callback and sends at most one input packet. Cold buffers are allocated in the Worker and transferred, not allocated as sample payloads during audio rendering. The receiver allocates bounded metadata/views/messages; this is not a zero-JavaScript-allocation claim.

At most256 controls may remain unapplied across current and in-flight packets. Requests/startup observations are bounded and timeout fail-closed. There are at most8 owners per context and a256 MiB planned-payload reservation. Before any Native/Worker construction, that reservation includes a conservative Rust linear-memory bound, all PCM credits and a1 MiB controller allowance. Actual Rust memory is checked after preparation. This accounting does not measure browser/Worker/Native implementation heap or whole-process RSS.

Cleanup attempts the actual transport SourceFence, Worker Engine free/acknowledgement, private gains and caller latency registration independently. It returns one idempotent promise. A clean Worker receipt follows the actual Rust Engine free; the Worker is then terminated. Transport heapFreed:false means JavaScript quiescence, not manual array deallocation. Partial prefixes report only actors actually returned. Missing/negative terminal evidence or failed independent cleanup remains quarantined; no timeout fabricates success or revives the stage. Capacity exhaustion refuses before changing existing owners.
