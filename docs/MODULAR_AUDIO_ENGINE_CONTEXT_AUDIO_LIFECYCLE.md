# Explicit context sleep/wake coordinator

These are review-only research helpers, not a supported general application suspend/resume policy. They do not wrap or replace Native AudioContext methods, change existing player call sites, or select a source provider. `contextAudioLifecycle.js` requires a same-context source with the strict contiguous live-freeze candidate API and an explicit review candidate source version (currently `8ca7d41660b2a010`). A legacy retire-on-suspend source cannot enter this contract.

`createContextAudioLifecycle(context, clock)` exposes `sleep(canSleep)`, `wake()`, `checkReady()`, `snapshot()` and `dispose()`.

Sleep calls the real Native suspend operation, awaits its resolution, and then obtains the frozen main/decoded counter certificate. A wake racing that transaction records intent and waits for certification before resuming. When no suspend transaction is pending, wake invokes Native resume synchronously before its first asynchronous wait, preserving the user-gesture frontier. Readiness waits for the first resumed frame proof, not only the Native resume promise. The sleep predicate is checked again after certification; activity arriving during suspension causes immediate certified wake. Interruption or an uncertified suspension remains a visible failure. Disposing the coordinator owns neither the shared source nor the AudioContext. Its diagnostic history is bounded to 32 entries.

`createWakeNoteGate({wake, on, off})` is a separate explicit adapter for first-key paths that cannot book a note until wake completes. The `on` and `off` callbacks are synchronous actual-ID operations. It returns stable opaque, transient tickets; it does not change the existing synchronous Generator liveNoteOn IDs. Releasing a pending ticket cancels the future note. A surviving ticket receives the actual note ID only after wake, and its release forwards that same ID. Capacity is checked before requesting wake. Cancelled but unresolved wake tickets retain their reservation until settled, preventing unbounded cancelled-promise accumulation. The default capacity is 128 and wake timeout is ten seconds. Tickets belong to one gate and are never song data. Sleep admission must include pending and held tickets (`gate.snapshot().pending === 0`) in addition to Generator.canSleepAudio: a key waiting for proof is already user activity, even before an actual instrument ID exists. Successor note profile `explicit-wake-note-tickets-v2` retains a release-failed actual ID and its activity/capacity reservation when caller off throws. Explicit off or dispose can retry that same ID; dispose attempts every voice and aggregates failures. Historical diagnostics are bounded to 32 entries.

Seventeen focused tests pass: suspend/certificate/resume order, racing wakes, first-proof readiness, changing sleep admission, cold wake, strict interruption, source identity, bounded history, first-key cancellation, exact ID pairing, capacity and release failures.

The separate Native desktop candidate page is `/reports/scripts/native-context-lifecycle.html`. It reuses the six-rate live source pause/wrap/reference proof through this coordinator and adds a real suspended racing-key transaction. One key is released before wake; another must produce exactly one nonzero original Native ConstantSource note through a muted analyser route, then release its exact ID. The first helper revision passed the lower three actual Native rates; its full receipt is retained as `reports/modular_audio/context-lifecycle-lower-first.json`. The separate v2 successor page `/reports/scripts/native-context-lifecycle-v2.html` also injects a failed Native release before stop, proves the real source/ID remains owned, and retries it. The v2 lower three rates passed, including the injected real-note failed release and successful same-ID retry (`reports/modular_audio/context-lifecycle-v2-lower-first.json`). Its upper shard retained a48k counter-certificate failure before note creation: Native destination441600 versus last rendered end441344. The coordinator surfaced the strict source refusal, not a note-ownership error. See `context-lifecycle-v2-upper-first-negative.json`. A later source-backed clock policy is required before general player adoption; neither old lower-rate receipt is relabeled as universal successor acceptance.

Read-only integration audit: the main idle suspender lives in `src/audio/idleContext.js`, installed by AudioStatus using Generator.canSleepAudio. Async Generator start, ambience and auditions can await explicit wake. Transport wake currently resumes and schedules without awaiting; it needs the same barrier. Synchronous MiniKeyboard and Tracks keyboard/MIDI callers need stable cancellation tickets or equivalent per-input tokens rather than silently making liveNoteOn asynchronous. All host wake is another explicit entry. LabApp and EnsemblePage also construct Generator on the shared context, and synth-lab behaviorLab/fmLab/lab/ensembleBackend directly resume that imported singleton; those are additional shared-context wake entries if this policy is selected there. Standalone Piano/Iowa/Strings/DIY and rainAudio construct independent contexts. Offline export needs its separately declared policy. No shared caller edits are part of this component.


The diagnostic follow-up proved the 128-frame stop-drain mechanism on the first 48 kHz cycle: Native frozen/first-resumed AudioParam frame 48512, previous rendered end 48384, unchanged BufferSource decoded 48384, start-drain 0. Both independent reference and low cursor were consecutive, with coarse/reference residual 1.7940377195976853e-9 and no diagnostic errors (`reports/modular_audio/native-freeze-drain-v2-48000-first.json`). Strict 8ca and this coordinator must refuse that real Native transition. Universal freeze compatibility is withdrawn. Runtime naming explicitly says review-only; a continuous-running 7a context policy or separately declared cold rebuild is the practical main-integration direction. This does not alter the independently useful cancelled-note ownership helper.
