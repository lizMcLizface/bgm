# Owned rack native dynamics

Current publication uses the separately versioned stamped-word transport. The original independent AudioParam fields could expose partial records during unsuspended normal-host restoration; ACK capacity alone did not make their payload atomic. Prior positive reference runs below retain their original version binding. See [the stamped transport contract](MODULAR_AUDIO_ENGINE_STAMPED_TARGET_TRANSPORT.md) for the retained negatives, formal publication proof, measured overhead and current acceptance boundary.

This is an explicit portable reference for the existing Effects Desk parallel compressor and added limiter. It does not change `graph.js`, `extras.js`, their defaults, or ordinary Instrument/VoiceCompressor routes. It reuses the accepted pinned native compressor kernel and its arithmetic profile without modification.

## Preserved paths and clocks

The compressor's original wrapper first assigns attack .005 and release .05. Its initial packet uses steps; later complete packets use 12 ms targets for threshold/knee/ratio/attack/release and the two gain branches. Dry is `enabled ? 1-mix : 1`; wet is `enabled ? mix*10**(makeup/20) : 0`. These projected Float32 gain targets are computed from the original JavaScript formula. Native k-rate parameters are observed every128 input frames; gain targets retain native a-rate four-lane recurrence and convergence.

The limiter starts from a bare native node, assigns knee0/ratio20/attack .002/release .09, then steps its initial ceiling. Later ceiling and outer on/off gains use20 ms targets. Dry0/wet1 represents on, dry1/wet0 represents off. Both branches remain present when one gain is zero, as in the native topology.

Dry has **zero delay**. Wet retains the native lookahead: the Float32 product `.006 * sampleRate`, truncated to frames and capped at1023. `wetLatencyFrames` reports the prepared kernel delay, rather than assuming6 ms at every rate. Native silence propagation uses a separate handler latency cache of256 frames before its first DSP pull; that initial cache is modeled in the silence decision, not substituted for the prepared kernel metadata. These are parallel paths with different latency, rather than one fixed composite latency. The port deliberately adds no dry-path compensation, no post-comparison alignment and no gain fitting.

Absolute context time and processed compressor time are separate. Explicit unpulled demand freezes compressor and parameter/gain state while absolute time can advance. Literal empty input can stop compressor DSP after the native tail/latency test while parameters continue processing. Connected native AudioBus silence flags are unavailable to JavaScript; this profile does not infer silence from zero PCM or claim generic transitive native graph equivalence.

The accepted live worklet uses the same portable DSP with an explicit host transport. Its single input/output compound node receives authored target metadata through8 slots, each holding7 Float32 projected native targets, exact integer frame halves, a finite sequence and an initial-step/later-target Boolean. Together with literal host demand this uses89 native metadata AudioParams. They supply **no native-generated smoothing or DSP coefficients**. Rust evaluates every curve and signal path. Sequence is bounded by16,777,215; authored frames by2^40-128. More than8 edits in one quantum is rejected before mutating packets or host snapshots. At most8 total edits may remain unobserved across quanta; the current reader rejects overwritten sequences. The acknowledged writer preflights this total bound before any sender mutation. The processor ACKs only after copying each payload into owned Rust state, including when DSP is unpulled. A cached stage connected into an inactive downstream branch may safely refuse its ninth outstanding edit; it never silently overwrites the pending chronology. Original `context.currentTime` is sampled once and must be bit-equal to `frame/sampleRate`; otherwise the facade refuses the call. Late observations retain the authored seconds and use native fresh-event clamping at the actual pull; counts/maximum lag are diagnostic. Overwritten/missing sequences fail closed.

The native constructor-only path creates exactly the original intrinsic scalar/gain state and constructor property writes.
