## Architecture and ownership

`synth-engine/src/lib.rs` is an original, dependency-free Rust DSP implementation. It does not incorporate Ameobea/web-synth or another synth engine. `public/synth-lab/processor.js` is the thin AudioWorklet bridge. Rust owns oscillator phases, filters, envelopes, voice allocation, timed events, modulation and chorus. JavaScript loads the module, edits parameters, schedules notes, drives the interface and records measurements.

The live instrument uses the application's shared AudioContext. Offline comparisons create separate OfflineAudioContexts. The audio worklet executes on the browser's audio rendering thread, rather than the UI thread. Wasm does not bypass the browser's audio callback deadlines, thermal limits or operating-system audio path. The demo deliberately excludes the fluid visualizer and generator; combined loads are measured separately on /tools/stress.html.

The Rust renderer uses fixed arrays and no per-block heap allocation. Memory is allocated with the instance, not grown while rendering. The worklet reuses its normal 128-frame output views; unusual output block sizes are supported too. Stats messages are sent roughly once a second. SharedArrayBuffer and cross-origin isolation are not required: parameters and bounded note batches use the MessagePort, while execution follows integer sample timestamps.

### Signal paths

| Family | Implemented structure | Important limits |
| --- | --- | --- |
| Prophet-inspired dual VCO | Two oscillators, B-master hard sync, B-to-A frequency/PWM and B-to-filter routing, separate filter/amp ADSRs, optional four-pole feedback cascade | Not a calibrated Prophet filter or a recreation of the original Poly-Mod circuit. |
| Jupiter-inspired dual VCO | Two oscillators, independent high-pass, selectable low-pass slope, unison and stereo width | Uses the same dual-VCO DSP primitives as the first family. Different recipes/routing are not separate measured hardware models. |
| CS-inspired layered | Two complete channels per note, each with resonant HPF then 12 dB LPF, independent oscillators/envelopes/LFOs, layer mix/pan and pressure | More flexible oscillator routing than the original. No CS-80 ring modulator, ribbon model or circuit-specific response. |
| Juno-inspired DCO | Shared pitch/phase clock for saw/pulse, divided sub, noise, amp envelope also controlling filter, stereo chorus | Independent B tuning, oscillator modulation, pitch variation and separate filter ADSR are ignored and their controls disabled. Chorus is a modulated delay, not a BBD model. |

Other controls shared by these models include sine/triangle/saw/pulse sources, coarse/fine tuning, noise, key tracking, velocity-sensitive amplitude/brightness, two LFOs, LFO fade-in, pitch bend, mod wheel, continuous channel pressure and per-note pressure through the backend API. LFO 1 offers sine, triangle, square, saw and sample-and-hold; LFO 2 is sine. The original modulation destinations remain; four extra per-layer routes now connect performance/envelope/LFO/random sources to five bounded destinations. Static voice pitch variation and optional continuously moving pitch drift are separate controls. See the expression checkpoint below for source units, curve laws and limits.

Saw and pulse use PolyBLEP correction. Sine uses an interpolated lookup table; triangle uses an analytic approximation. The filters are topology-preserving state-variable stages, with a cascaded pair providing the 24 dB option. Nonlinear input drive and a bounded output shaper are included, but there is no oversampling. Audio-rate oscillator modulation and the corrected hard-sync reset can still alias, particularly at high pitches/depths. The subtractive prototype is not a circuit-accurate emulation or physical string model. Operator FM now has its own kernel and laboratory.

### Polyphony and timing

Capacity is 1–32 independent note voices, each with 1–4 unison lanes. The layered model doubles the active channels per note. The extreme 32-note × 4-unison × 2-layer configuration runs 256 subtractive lanes, before counting the individual oscillators. Capacity is a limit, not a statement that every device can run that configuration in real time.

Each live attack receives a unique note ID. Note-offs affect that ID, so a stale release cannot stop a replacement voice after stealing. Allocation prefers free voices, then released/quieter voices, with age breaking ties. A short last-output crossfade softens a steal. Sustain defers envelope release; panic clears voices, the pending queue and effect state. The JavaScript bridge ensures a very short key release cannot be scheduled before its attack. Changing architecture or capacity restarts the isolated instrument and clears held notes.

The queue holds 4,096 events, sorted by frame. Overflow and late submissions are counted and displayed alongside active voices, steals and block peak. Late events execute at the current sample rather than disappearing. Oscillators/envelopes render sample by sample; frequency and filter targets update every 16 samples, including the first sample of an attack. Filter coefficients interpolate between targets. Not every control change is smoothed: editing waveform, mix or tuning while holding notes can produce discontinuities. More comprehensive parameter smoothing is a refinement item.

The plain numeric ABI has 12 global and 99 per-layer parameter slots; IDs are append-only and defined in `src/synth-lab/patch.js`. The first 86 layer slots retain their meanings; imported older patches inherit disabled acoustic mixes, disabled routes and their original curve defaults. The module exports API version 1, which the worklet checks. Its core contract is `engine_init`, `engine_param`, `engine_event`, `engine_render`, stereo output pointers, `engine_panic` and `engine_stat`. `engine_set_frame` aligns a newly created live instance to the AudioContext sample clock. IDs and event frames are distinct from musical MIDI pitches. There is no user-facing MIDI-device integration in this slice.

## Comparison and benchmark protocol

Both pages can render either backend from the same timed chord, arpeggio, held-chord or stealing-stress fixture. Set tempo, note capacity, sample rate and dry/wet choice before rendering. A/B playback shares a seek position, synchronized waveform cursors and bar/beat label. Both WAVs and the raw measurements can be downloaded. Optional RMS matching only attenuates playback/downloads; measurement rows and waveforms retain the engines' original output. Matching loudness does not make their spectra or envelopes equivalent.

The current-engine adapter uses the actual existing Instrument implementation. It translates compatible oscillator, tuning, ADSR, filter/LFO and chorus controls. It cannot reproduce independent layer B, shared DCO clock, the new mixer, independent HPF, LFO 2, PWM/audio-rate modulation or continuous pressure. Native filter/envelope and oscillator behavior also differ. This is a musical and architectural reference, not a bit-identical A/B or equal-DSP performance contest. Use a dry dual-VCO patch for a closer structural comparison. In particular, the current backend is doing less work for a layered patch.

Benchmark runs include one warm-up then three measured renders per engine, alternating engine order. The report separates preparation and OfflineAudioContext render wall time, records sample rate/capacity/unison/layers/browser, and reports output peak, RMS, DC, non-finite and full-scale samples. The median excludes warm-up. Offline wall time includes browser overhead and is affected by other machine activity. It does not measure live audio-thread CPU, hardware latency or audible dropouts. No automatic device-quality policy is inferred from it.

## Effects design — implemented in the following checkpoint

User highlighted long-tail reverb as an existing bottleneck. The first laboratory benchmark only implemented chorus, so its original results do not establish the cost of a full ambient ensemble with reverb and delay. The following checkpoint implements this investigation before the FM expansion.

The current generator uses native convolution (`src/nodes/reverb.js`) with decoded impulses cached by sample rate/type, but separate convolver processing per Instrument by default. Optional `sharedReverb.js` buses share processing by impulse type. Phone defaults select sharing plus the light mono/two-second impulse; ordinary full impulses are capped at three seconds. These are existing compromises, not evidence that longer reverberation is intrinsically unaffordable. Reverb is already per instrument rather than per polyphonic note.

Proposed design: a separate stereo effects processor with sends from instruments to one or two shared room/hall buses. Keep chorus or other sound-defining insert effects with the instrument. Exposing an audio-input effects worklet lets both the existing Instrument and new Wasm synth feed exactly the same new reverb/delay, and permits a gradual generator integration. Preserve send levels/mutes and effect ordering explicitly; sharing is not automatically sonically identical to the current per-role insert chain.

Start with a modulated feedback delay network (FDN): 8/16 lines as quality tiers to evaluate, diffusion/early reflections, an efficient energy-preserving feedback mix, per-line decay gains, feedback damping, pre-delay, width and subtle modulation. Separate decay time from room size/network order. With a fixed network, increasing RT60 changes feedback/filter coefficients rather than allocating a tail-length impulse or adding delay lines. Steady processing cost should therefore stay approximately fixed as decay increases. It still runs longer after the input stops; sample rate, quality tier, modulation, bus count and optional pitch-shifting effects affect cost. Long-decay stability, denormals and tail-aware sleeping need explicit handling. This is a design target, not a measured implementation result.

Add stereo/ping-pong feedback delay with tempo sync, dotted/triplet choices, feedback-path filtering, bounded feedback, wet/send levels and click-free time changes. Longer echo decay principally changes feedback and processing lifetime; maximum repeat spacing determines buffer size. Native DelayNodes are already efficient and should remain a baseline. Do not assume a Wasm delay or a port of native convolution will be faster solely because it is written in Rust.

Comparison should isolate dry synth, delay only, reverb only, then combined effects. Feed identical sources into native convolution and the new effects processor; include short/medium/long decay targets, impulse/pitched/percussive/held inputs, long tail-only spans and 1-versus-multiple shared buses. Capture finite output, decay curves/band damping, memory, preparation/render time and live behavior on Firefox/real phones. Match decay and perceived wet loudness where possible; finite output and fast offline rendering do not establish pleasant diffusion or a sonic match. Preserve full tail exports and measure both a fixed-duration comparison and the cost until silence, rather than silently shortening the slowest tail. Any short-IR-plus-algorithmic-late-tail hybrid should be a later comparison option if early-room realism is lacking.

Background: [Julius O. Smith's delay-line damping design](https://www.dsprelated.com/freebooks/pasp/Delay_Line_Damping_Filter_Design.html) explains decay control for fixed FDN delays; the [W3C convolution architecture note](https://www.w3.org/TR/2015/WD-webaudio-20151208/convolution.html) describes partitioned FFT processing. These inform the proposed architecture; no external DSP implementation has been incorporated.

## Build and verification

Three compiled modules are bundled under `public/synth-lab/` (`core.wasm`, `effects.wasm`, `fm.wasm`), so normal development/building needs Node, not a local Rust installation. `build.json`, `effects-build.json` and `fm-build.json` record each API version, source/binary hashes, compiler and size. Source hashing normalizes line endings. The hash check catches a stale source/artifact pair; it is not an independent attestation of a compiler run.

To rebuild with an installed Rust toolchain:

```sh
rustup target add wasm32-unknown-unknown
npm run synth:build
npm run synth:check
npm test -- src/synth-lab
npm run build
```

All four crates (subtractive, FM, room effects and instrument inserts) have no external dependencies. Cargo release uses LTO, one code-generation unit and abort-on-panic. `SYNTH_CARGO` can point to Cargo explicitly. The build script also recognizes the ignored `.tmp/rust-tools/` toolchain used for this prototype; it does not require global PATH changes. Build output under each crate's `target/` is ignored. Ordinary `npm run build` checks that every bundled Wasm matches its sources before bundling the laboratory pages and main app. Full `npm test` remains the generator regression check.

## Current checkpoint — shared effects, classic routing and FM

The separate original effects crate is implemented and available to both live synth backends. It has an 8/16-line modulated FDN, two input diffusers per channel, early reflections, damping, pre-delay, width and filtered stereo/ping-pong feedback delay. Echo time changes crossfade taps. Dry/reverb/delay inputs are separate so multiple instruments can share one bus with their own send levels. The UI provides tempo divisions, and patch export/import includes effects; older subtractive patch files without effects import with bypass enabled. A tail-aware sleep guard accounts for pending delay taps before skipping silent DSP. Clear/bypass/quality changes reset the effect tail. Default live lab patches now use these effects; the dry benchmarks still exclude them.

The tail page captures one source once and sends the same PCM through both paths. It compares synthetic requested-decay convolution or the existing capped room impulses, with a matching native filtered-delay reference. Full conservative tails and fixed ten-second windows are explicit choices. WAVs, synchronized playheads, RMS attenuation, decay plots, fitted finite-window RT60 and reports are implemented. Memory reporting distinguishes the whole Wasm linear memory from native IR sample storage; it cannot report browser-internal convolution memory and must not imply equal measurements. The kernel's fixed 6.6 MiB storage reserves its maximum 192 kHz buffers; its download is about 59 KB after moving zero buffers out of the initialized data segment.

Chrome/Firefox comparisons rendered short and long reverb, delay-only, combined effects and current room references without non-finite/full-scale samples or browser errors. At 48 kHz, an 11.2-second fixed-window, 20-second-decay test rendered in 244.6 ms FDN / 4,051.6 ms synthetic convolution in Chrome; Firefox measured 197 / 1,461 ms separately. These were single offline runs, not a universal speedup or acoustic-equivalence claim. Both used unchanged Wasm memory as decay increased. The fitted long decay was about 18 / 19.4 seconds within the truncated window. An eight-second full-tail case fitted about 7.9 seconds in both paths. Native delay was faster than the full Wasm effects processor (Chrome 23.7 versus 69.2 ms for the impulse test), with near-identical peak/RMS. Short-tail FDN tests sleep earlier; total rendering time is not proof of constant active cost per block.

The classic subtractive pass adds B-master hard sync with a short polynomial reset correction, B-to-filter audio-rate modulation, independent pulse offsets, B low-frequency/keyboard-tracking modes, A-only envelope pitch routing, pressure-to-amplitude/pitch, oscillator ring mixing and an optional four-pole TPT feedback-cascade approximation. The cascade is a distinct filter path, not a measured SSM/CEM or Jupiter/Juno filter. CS mode keeps its independent state-variable HPF/LPF stages; unsupported choices are disabled. Sync sweep and Independent poly motion demonstrate the added routes. Sample-timestamped retune events glide held note IDs without retriggering either envelope; the live demo includes octave-glide buttons. Audio-rate modulation, triangle and sync still need dedicated alias-spectrum work; the subtractive path does not yet oversample.

The new FM instrument and its build/ABI are described in [FM_SYNTH_PLAN.md](FM_SYNTH_PLAN.md). It supports four/six operators, six starting topologies plus forward matrix edits, one feedback operator, separate time/level envelopes and expression, and 1×/2×/4× processing with an FIR decimator. Feedback delay periods stay constant across quality modes and output saturation is inside oversampling. Gain, feedback, global index and operator levels are smoothed while held. Tests and browser checks exercise independent note IDs, tuning, stress, sustaining/stealing, held glides, dry/wet rendering and file import. No shared-memory worker pool, hardware patch compatibility or generator migration is included.

All four built laboratory pages and the main generator load in Chrome and Firefox; both browsers play the selected live synths and render the comparisons without browser errors. The additional fixed-frequency and non-sine FM recipes render finite, non-silent output in both. A final Chrome 16-note stress benchmark on Bowed glass pad (12.48 seconds, 48 kHz) measured median 1,964.7 ms at 2× versus 3,882.0 ms at 4×, excluding warm-up. This compares quality cost inside the same engine and does not establish mobile/live headroom. The held-glide/wet passage also renders correctly. Intermediate benchmark outputs are released rather than accumulated. ## Listening correction — sustained body and reverb audibility, 18 October 2026

User feedback identified that the synth's held body was much thinner than the native comparison and that a nominal 20-second reverb disappeared perceptually after the attack. The earlier broadband RT60 fit and finite-output tests did not establish a useful wet level or midrange decay. These measurements remain historical evidence of that earlier implementation, not validation of its perceived fullness.

The subtractive mixer reserved 6 dB before the driven filters and never restored it. Compensation now happens after filtering, preserving the input drive and envelopes. Held-note measurements verify that the body remains steady until note-off; this was primarily a level mismatch rather than a held envelope continuing to decay. Five-voice brass's held RMS rises from 0.0295 to 0.0588, versus 0.0748 in Chrome's current-engine reference. Eight-voice silk measures 0.0814 versus 0.0805. These are recipe-specific observations, not a universal loudness calibration. The native engine compresses its mixed voices and uses a different filter envelope and 12 dB filter; the new engine uses soft saturation, an independent filter sustain and selectable slopes. Its transient/body contour should not be presented as identical. Synth plots now include the selected playback attenuation, while numerical metrics remain raw.

The reverb return incorrectly applied another `1/sqrt(N)` after energy was already distributed across N delay lines. Signed return taps now sum at unity; normalization remains on injection and the orthogonal feedback matrix. This restores 9/12 dB of late-return level for 8/16 lines without increasing feedback. Damping is now a decay-dependent shelving loss rather than an unrelated low-pass loss on each traversal: the high-frequency asymptote targets half the base RT60, and the existing Hz control sets the darkening corner. Four-point Lagrange reads reduce repeated fractional-delay interpolation loss. These are approximations with modulation and modal coloration, not exact RT60 at every frequency; the [damping-filter design](https://www.dsprelated.com/freebooks/pasp/Delay_Line_Damping_Filter_Design.html) and [interpolation discussion](https://www.dsprelated.com/freebooks/pasp/Delay_Line_Signal_Interpolation.html) explain the underlying constraints.

An append-only effects parameter, `reverbReturn` (index 16, −24 to +18 dB, default 0), controls wet output independently of send/feedback/decay. Changes are smoothed sample by sample; old patch files/URLs inherit 0 dB. The convolution adapter uses the same return gain. Positive return gain extends the conservative export bound. The fixed Wasm memory stays 6,946,816 bytes and the effects binary is 59,124 bytes; decay does not allocate an impulse.

The effects comparison defaults to raw send levels. Optional matching now uses post-source tail RMS, preventing the dry attack from dominating the comparison. The table reports the first tail second and the second beginning five seconds after the source ends, alongside the fitted decay. Shared waveform magnification reveals quiet structure without independently normalizing either trace. Decay is explicitly labelled RT60: 20 seconds means approximately 60 dB down after that time, not 20 seconds at a constant level. The existing room reference still has its real three-second cap.

Chrome and Firefox rendered identical captured PCM through the corrected network and native references without page errors or non-finite/full-scale samples. For the 48 kHz, short-chord, 20-second case at send 0.22, the network fit is 19.4 s versus 19.9 s synthetic convolution; the first tail second is −36.3 versus −39.3 dBFS and the +5 s window is −51.0 versus −54.1 dBFS. At eight seconds the fits are 8.1/7.9 s. With the user's send 0.8/current-room configuration, the network's tail windows are −25.1/−39.8 dBFS and its fit is 19.4 s; the short native room ends sooner as expected. The source synth itself is also 6 dB louder after mixer correction, so historical before/after absolute output differences must not be attributed entirely to the reverb.

Three subtractive wet held-chord recipes and the FM wet held-glide comparison pass in both browsers. Layout fits 390 px without document overflow. New regression coverage protects absolute 1 kHz tail level and sustained decay at 44.1/48/96 kHz with both network sizes, sample-consistent live return edits, silent matching references and held synth body level. The full suite passes 634 tests across 87 files; production build passes with the existing ambience/chunk-size warnings. QA artifacts are task-local `tail-calibration-before.json`, `tail-calibration-calibrated.json` and `reverb-feedback-{chrome,firefox}.json` plus screenshots. Offline results remain listening aids rather than phone/live-budget evidence.

**Phase:** synth/effects listening and calibration within sound-engine validation. **Remaining:** listening approval of these levels, alias/filter/chorus refinement and real-device/live shared-ensemble budgets. **Direct next step:** audition the corrected 8/20-second tails at ordinary sends, including the default pad/FM recipes, before full-ensemble shared-bus integration. ## Delay-only performance correction — 18 October 2026

User observed that the Wasm delay comparison was much slower than native delay despite the reverb improvement. The cause was unused DSP: the FDN, early-reflection taps, diffusers, damping and modulation still processed every sample in delay-only mode. Zeroing the reverb send did not bypass that work.

The reverb network now has independent activity tracking. Actual direct-room input wakes it at the existing block boundary; delay-to-room routing wakes it when an echo actually arrives. Turning down either send leaves an existing tail running. A half-second quiet guard covers the longest pending pre-delay/reflection/diffuser/FDN path before parking that network while dry/echo processing continues. Whole-bus sleep and explicit clear/bypass retain their existing roles. No allocation or buffer-size increase is introduced. Append-only diagnostic stats 4/5 expose reverb activity and cumulative FDN sample count; live lab stats show active/idle reverb independently of the bus. The comparison labels now say Wasm/Native, since a delay-only Wasm pass does not involve an FDN.

The user's 48 kHz, 409 ms ping-pong delay/send 0.8/feedback 0.4 short-chord fixture renders 6.75 seconds of audio. Chrome's warm-up-excluded median fell from 150.3 ms to about 23 ms (final run 23.3 ms); native delay measured 16.5 ms. Firefox's optimized run measured 17 ms versus 11 ms native. These are desktop offline wall times, not live CPU/device budgets or proof that Wasm is universally preferable. Native delay remains a reasonable component of a future hybrid shared-effects path; fixed-size FDN reverb and native delay solve different computational problems.

Captured before/after kernels produce sample-identical six-second delay/reverb/combined fixtures at 44.1/48/96 kHz. Delay-only runs report zero FDN samples. Regression tests cover delayed echo-to-room wake-up, tail preservation after a send reaches zero, independent reverb sleep while echo/source keep the bus active, and reactivation. All 636 tests across 87 files and the production build pass; existing ambience/chunk-size warnings remain. Task QA artifacts: `delay-chrome-before.json`, `delay-chrome-after.json`, `delay-firefox-after.json`, and `delay-sample-audit.json`.

**Phase:** sound-engine performance validation. **Remaining:** alias/filter/chorus refinement and real-phone/live shared-ensemble budgets. **Direct next step:** benchmark several instruments sharing effects, including a native-delay/Wasm-reverb hybrid, before generator-backend integration.

## Shared ensemble and native-echo hybrid — 18 October 2026

`/tools/ensemble-synth.html` now compares dry synthesis, effects per instrument, shared Wasm effects, and shared Wasm reverb with native echo. Its deterministic four-part fixture combines Bowed glass pad (four held FM voices retuned between chords without reattack), Tine constellation, an adapted DCO bass and a soft subtractive lead. Two/four/eight instruments, one/two/four shared rooms, four/eight bars, FM quality, rate, tempo, decay and master level are selectable and URL-backed. The original library recipes are cloned for fixture adaptations rather than changed. Each part has independent dry/room/echo sends and stereo placement. Additional rooms use smaller/darker settings; the per-instrument reference retains each part's assigned room settings.

Full-chain rendering includes actual synthesis and effects. Captured-stem mode renders all source channels together once, then feeds identical captured PCM into every effects path, reporting capture time/PCM storage separately. Both modes export full conservative tails. The comparator provides synchronized playback/waveform cursors, readable bar labels, held-pitch trajectories, raw peak/RMS, effects-Wasm memory, JSON/WAV downloads and warm-up plus three alternating-order measured runs. Final result buffers are published atomically, including reverse-order benchmark runs. Per-instrument modulation/output saturation differs from a shared nonlinear bus; those paths are musical/cost references, not a bit-identical promise.

Live mode runs the full source/effects graph on the existing shared AudioContext, with looping sample-timestamped events, independent note IDs, level audition, stop/clear and JSON session reports. One cycle is queued ahead; overdue cycles are counted and skipped rather than replayed. Queue late/dropped, steals, scheduled/missed cycles, browser-reported latency, visible frame pacing and supported main-thread long tasks are exposed. ## Spectral and alias diagnostics — 18 October 2026

Implemented /tools/spectrum.html as the next sound-engine validation slice. This is validation infrastructure; no kernel, generator patch or preset sound changed in this slice.

Method: a settled 65,536-sample four-term Blackman-Harris window; one-sided power normalized by window energy; a five-bin guard around expected harmonics; integration from 20 Hz to 80% of Nyquist. Drift, noise, chorus and pitch/envelope movement are disabled. The base pitch is nudged to an odd FFT bin so many folded partials do not simply coincide with allowed harmonics. Subtractive B tuning is relative to A; the hard-sync probe explicitly keeps master B at the diagnostic fundamental while A runs near three times faster. Window main-lobe reasoning follows [Julius O. Smith's sinusoid analysis](https://www.dsprelated.com/freebooks/sasp/Spectrum_Analysis_Sinusoids.html).

The reference uses 4x host rate at 44.1/48 kHz, or 2x at 96 kHz to respect the kernels' 192 kHz host ceiling; FM uses 4x internally at that higher host rate. A centred 64*factor+1-tap Blackman-Harris-windowed sinc low-pass is applied before downsampling, with its corner at 90% of target Nyquist. Analysis stops below its transition band. See [downsampling and aliasing](https://dsprelated.com/freebooks/SASP/Downsampling_Aliasing.html). This is a convergence reference, not an alias-free oracle. Off-harmonic energy misses aliases that fall on valid harmonics, while feedback can produce legitimate nonperiodic energy. Reference magnitude distance also includes rate-dependent filter/oscillator behavior and floating-point phase differences. Neither metric establishes a universal audible alias threshold.

The reproducible **npm run audit:synth-spectrum** sweep covers 9 probes x 3 registers (220 / 997 / 3,137 Hz targets) x 3 rates (44.1 / 48 / 96 kHz): 81 cases, all finite and below full scale. Optional -- --deep raises modulation amount to 3; the >10 dB high-register FM regression requirement applies only to the default-depth probe. Reports are saved in .tmp/spectral-audit/matrix.json or matrix-deep.json. The analysis does not establish live CPU, mobile headroom or a quality policy; single-run timings are diagnostic only.

At 48 kHz near 997 Hz, the bright pair's off-harmonic ratios are -22.2 / -75.2 / -78.6 dB for 1x/2x/4x; the deeper stack measures -4.1 / -27.1 / -73.7 dB. Near 3,137 Hz the pair measures -0.9 / -9.2 / -65.4 dB, but the deep stack still measures -1.2 / -2.1 / -10.9 dB. Thus 4x helps substantially in the pair but is insufficient to clean an arbitrarily deep, high-register stack. Strong-feedback figures must not be interpreted as pure alias ratios. At the same high pitch, native subtractive sync/PWM measure -32.9 / -26.5 dB, versus -50.8 / -39.4 dB for the filtered higher-rate references. Native saw/triangle measure -40.4 / -42.8 dB. These probes identify audio-rate PWM and high-register/deep modulation as refinement priorities; they do not justify silently changing every musical patch.

Its order is **saturation → low shelf / mid peak / high shelf EQ → six-stage stereo phaser → stereo feedback flanger → stereo chorus → output trim**. The host creates one chain per instrument, before its room/echo sends. It is not allocated per note and contains no long room reverb. The same module accepts any stereo AudioNode source, including the current-engine laboratory adapter. FM can therefore use chorus and the other inserts without duplicating the subtractive core.

EQ follows the bilinear-transform coefficients in the [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/). Phaser uses cascaded first-order all-pass sections with bounded signed feedback; flanger uses a short variable delay with bounded signed feedback. Chorus uses opposite stereo delay motion, four-point Lagrange interpolation and decorrelated-power compensation. Saturation has independent mix/drive and DC removal. EQ/drive/feedback can increase raw peaks; output trim and reported peaks expose gain staging rather than silently normalizing every patch. This is an original software effect chain, not measured hardware/BBD emulation. Saturation runs at host rate after FM decimation; it does not inherit FM oversampling and can alias at strong/high-frequency settings.

Parameter and master-bypass changes slew over 20 ms; EQ/phase targets refresh every 32 samples. Master bypass fades to dry, then clears hidden history once. Individual zeroed modulated stages clear after fading out. Disabled inserts are exact transparent copies and take the wire path. Active chains reserve fixed delay/state arrays, allocate nothing per block and never grow memory. Conservative exports include insert filter/feedback tails before the subsequent room/echo tail. Full bypass/clear and worklet EOF/disposal release state explicitly.

Patch JSON adds optional `inserts` host metadata, independent of the synth and room parameter ABIs. Import clamps/defaults every field; older patches have all inserts off. Subtractive internal chorus remains a separate original control, so the lab explains how to avoid unintended stacking. Both live labs expose the insert controls and peak/memory stats; their wet offline comparisons include inserts, while dry comparisons exclude inserts/rooms/echo. The ensemble applies enabled inserts before splitting dry/room/echo sends. Captured stems already include them and are not processed again; source windows include their tails. Reports expose insert count separately from room memory, whose existing column still excludes source/insert/native/PCM/graphics memory. The default ensemble's earlier patches have inserts off and allocate no insert worklet there.
