# Explicit ordered live send / sum

This NEW opt-in component ports a bounded Gain-per-slot and Float32 sum boundary. It does not select a Generator path or replace the original implicit Native fan-in. Existing mixer/Main/Graph profiles are unchanged.

## Exact ordering and channel contract

The immutable recipe contains 1..8 uniquely named slots in caller order. Each slot has one physically connected owned source, fixed one or two channels, raw initial gain in 0..4, and an explicit constructor-assignment Boolean. Output is stereo. A mono slot is speaker-duplicated, with no attenuation or pan replacement. Four cohort claims per context bound 32 simultaneous slots.

The sum follows pinned Chromium AudioChannel::SumFrom: skip explicitly silent source channels, copy the first non-silent contribution, then add each following contribution in recipe order with Float32 rounding. This preserves first-copy signed zeros. It differs from an unconditional zero-initialized addition loop. Original AudioSummingJunction obtains its rendering order from a HashSet; this profile never infers or promises that arbitrary order. Its independent Native reference is an explicitly nested sequence of two-input unity Gains.

The kernel reuses the accepted `rack-filter-normal/src/timeline.rs` read-only, and the existing Main03eb gain multiply/scalar-zero branch. Set, target and cancel retain raw Float64 seconds/value/tau and every repeated call. The control writer supports one whole-cohort reservation, 32 TOTAL unobserved records across all slots, and 256 entries per slot. `seconds:'now'` resolves separately for every row at publication; the subsequent actual context timestamp is read separately for its authored-frame metadata. Space callers keep their authored seconds and bar-derived tau. Capacity is checked for every row before any metadata field is written. A partially published batch is terminal. Credits come from actual Rust read-only observations, with older unseen authors conservatively retaining debt.

## Source activity authority

`declareOrderedSendSource` is an EXPLICIT CALLER DECLARATION for a continuously processing, true-returning AudioWorklet output. The caller owns its source, fixed layout and lifecycle, supplies `check()` and a real retained `borrow()`, and must prevent upstream terminal/layout changes until all borrows release. The declaration is neither cryptographic verification of arbitrary worklet code nor inference from array contents. Missing, foreign or opaque source contracts refuse before actor creation. Native Gain/filter/tail output, ended sources, unknown bus flags, dynamic layout, and multiple sources sharing a slot are not admitted by this live host.

A continuously processing AudioWorklet output is Native non-silent even when all numeric samples are zero. The host never guesses a Native silence flag from PCM zeros. Before input attachment, physically empty slots are parameters-only: timelines advance, with no program input. After source attachment the fixed continuous provider contract applies. Once a physical slot has been observed, its later disappearance is a terminal typed refusal before another Rust quantum. Initial live attachment has a bound of64 actual processing quanta; no callback/ready state is invented for pre-render Offline construction. A complete first zero-valued cohort is still logically non-silent. Standalone Rust also has explicit authored silent and parameters-only activity modes for exact bounded fixtures. The output worklet itself has continuous non-silent Native output semantics even when its internal logical sum is silent; downstream opaque Native activity equivalence is not claimed.

Cohort stats/flush/activation/dispose packets require the exact captured four-field identity and exact per-kind field shape. Missing/foreign/extra identities and malformed disposal reject before queue or Rust release mutation. Source7a keeps its separate private immutable clock-link protocol; cohort identities do not replace its generation/rate validation. Cached hosts without all new protocol/terminal capabilities refuse before actor creation.

Sources remain private. The component completes same-port clock binding, then an actual isolated arm/activation fence before connecting any program input. Only the stable output becomes public. This prevents a control pump from advancing an already connected upstream Native source cursor. Source borrows are retained through the cohort's actual typed release receipt.

## Clock, resource and cleanup policy

The host uses the unchanged Source7a `native-context-clock-source-v1` controller and exact Native integer decoder. No raw-global epoch fit, timestamp rebasing, Native coefficient bridge, or output shift is used. Once processing begins, Native frames must remain contiguous. Observed live suspension permanently fails this owner. Offline rendering explicitly uses the previously accepted `offline-freeze-v1` Source7a contract; constructor/spec binding completes without waiting for an audio callback.

Each cohort has a private unity program output and zero-gain control pull. The control pull never receives upstream program input before activation. Rust allocates all timelines, input and output storage at construction. The six-rate eight-slot allocation audit processes 128 quanta, including control insertion/pruning, with **0 allocations, 0 reallocations and 0 frees** during the watched interval; actual Wasm memory is **1,310,720 bytes per cohort**. Four such instances therefore account for 5,242,880 Wasm-memory bytes. These are actual Wasm buffers, not total browser/Native/AudioParam heap or hardware-deadline evidence. Source7a's context clock storage is separate. The host has 580 a-rate metadata/control descriptors, bounded 16 pending FIFO requests, and 32 queued stamped records.

Disposal synchronously publishes a separate literal-Boolean one-way terminal gate BEFORE any Native edge removal or await. Once observed, terminal callbacks write zero and quiesce before input, Native clock and DSP checks; they neither free Rust nor produce a terminal ACK. The exact-identity dispose message still owns Rust release and the typed receipt. A failed gate write keeps program edges intact until real release proof; its cleanup error remains visible. Disposal then attempts every captured edge, requires actual SourceFence release (or real context close), keeps clock links through that receipt, and releases source borrows. It joins pending activation/borrow work before cleanup, so a late source owner cannot escape retirement. Unexpected Native/clock/borrow cleanup failure rejects the observed Promise and retains the cohort claim until real context close, even if the Rust actor itself has released. A failed source borrow cleanup is separately retained as uncertainty. Whole-cohort source acquisition uses monotonic `performance.now()` and is observed for at most 5000ms (wall-clock adjustments cannot extend it), and actual retained-borrow release observations run in parallel with a 5000ms bound. These are uncertainty budgets while the event loop runs, not physical/hardware deadlines. At most16 provider observations are retained per eight-slot cohort. A genuine late acquired owner is cleaned without attachment or parent mutation; a late clean result never revives an already rejected operation/disposal or releases its quarantined cohort claim. Known actual actor release remains separate from uncertain external provider cleanup. No consumer disposes a shared clock controller.

## Application adoption boundary

This leaf is not yet selected by Generator. Its one-output declaration deliberately refuses current five-output RoleWander actors; application wiring needs a separately captured actual output-index/channel authority and real source borrow. Existing bus/space rack outputs also contain Native processed/bypass gain mixing; a Native fan-in or arbitrary Gain must not be relabeled as a worklet or transparent unity route. Four steady cohorts can cover dry8, bus6, space6 and master2 only when both return sources have independent admitted output authorities. Old/new whole-runtime overlap would require8 and must refuse before mutation under the current4-cohort budget. Editable source-slot changes and whole-runtime Wander replacement are different lifetime operations. Global `masterBus.gain` remains a separate Native .02 volume target/getter boundary in AudioStatus; distributing it into pre-sum slot gains would alter Float32 arithmetic and is not done.
