# Clocked rack compressor and limiter

This new opt-in adapter uses the accepted Native context clock source `7a0838a735108706` around the existing rack compressor/limiter implementation. It preserves the original seven independent AudioParam control lanes, their separate currentTime reads and literal call order, the 32-record stamped publication protocol, and the existing Rust kernel. It does not select itself in the application environment.

The numeric dependency is the original `rack-dynamics-calls` Wasm: 81473 bytes, SHA-256 `db64b55a617dd518d7e9d215e908192972dd1780c9f9f8c400b8d9081cbccfe6`. The historical normal profile `5a236fa5de4b0607`, its assets and all old clock policies remain separate. New assets are `public/rack-dynamics-clocked/{build.json,processor.js}`; no second numeric Wasm is emitted.

The need for this adapter is an actual assembled All failure: a restored host reached the old stamped reader with an authored frame greater than its stale AudioWorklet global frame. The original Width/Ring graph-churn proof independently showed Native BufferSource and AudioParam clocks at frame 61440 while the same callback's global frame was 61056. The new adapter decodes the independently running Native clock fields; it never clamps control timestamps, fits an epoch, shifts input audio, or drops an active block to recover.

`prepareClockedRackDynamics(context)` returns the existing synchronous `(context, {kind, onError})` leaf-factory shape. Owners support compressor and limiter, whole-packet patches, individual lane calls, snapshots, meters, clear, disposal, and the explicit `prepareInitial()`/`arm()` lifecycle. The caller must patch and await initial preparation before wiring output or upstream program audio. The actual createRack integration includes its optional compressor in that preparation barrier.

Each owner has a physically isolated Native Gain input bridge. In a running context, preparation temporarily pulls only the Rust worklet through its own zero-gain control sink with Boolean host demand false and no program edge. It waits for every current initial control sequence to be acknowledged, removes the entire temporary route, then attaches the program bridge. Cold/suspended Offline construction books metadata and attaches without waiting for a rendering callback; the verified `offline-freeze-v1` source policy is explicit.

Initial absent or torn clock publication can defer at most 64 callbacks only before the first valid clock, with literal all-zero demand and zero physical input channels. It advances neither the Rust processor nor the control reader or ACK watermark. Active input, mixed or malformed demand, subsequent bad clock words, a changed generation, or an expired clock remain strict failures. This is not a general inactive-input heuristic.

Clock metadata input edges remain attached until the processor independently acknowledges its disposal. Typed source retirement releases Rust state and reports a distinct retirement notification, so it does not reject an already pending disposal acknowledgement. Unexpected cleanup failures are retained and aggregated; one owner's disposal does not retire a surviving owner's shared source.

Thirty-two focused tests pass, including real unchanged Wasm at six rates with active Native-authoritative frame 512 while the raw global remains 128, strict pending/refusal tests, physical bridge isolation, cancellation during preparation, cold Offline readiness, independent owners and disposal fences.

The fixed Native desktop page is `/tools/clocked-rack-dynamics.html`. Its ten cases per selected rate reuse the actual normal rack Native reference scenarios: mono/stereo construction, routing/reorder, JSON cold reload, and separately timed compressor/limiter lanes. Bounds remain maximum absolute error and relative RMS error each <= 1e-4. Initial host `532a70dddc6ffd5a` passed all 60 actual Native comparisons at all six rates. Five rates were PCM exact; the 96 kHz maximum absolute error was 1.043081283569336e-7 and maximum relative RMS error 6.014669642922696e-9, within unchanged 1e-4 bounds. Full reports are retained under `reports/modular_audio/clocked-dynamics-532a-*.json`, and accepted host bytes are separately archived.

It does not wait for AudioParam consumption while rendering is suspended. Withheld, wrong-generation and disposed-before-bind tests pass. Its actual cold 48 kHz ten-case Native gate passed with maximum absolute error exactly zero, proving the MessagePort receipt does not require an Offline render callback.
