# Context preparation reservations

The main-thread registry is connected to the existing idleSuspender through a minimal bridge. Without a preparation reservation, Native suspend/recheck/resume behavior stays the same. It does not change Generator, any existing factory or clock profile, or the normal UI's runtime choice. Environment selection remains uninstalled; the registry alone does not make replacing the long-lived Generator safe.

`reserveContextPreparation(context, options)` claims a reservation synchronously, before asynchronous loading or Native resource creation. There are at most 16 context tickets total, including published resource owners and owners being retired. A preparing, cancelling, retiring or cleanup-failed ticket blocks idle admission. A published owner does not block idle by itself: the publication callback must install its selected continuous-context policy before the preparation hold is released.

`lease.ready` waits for any already-issued registry idle suspension and the corresponding Native resume before resource creation. `wake: true` explicitly invokes Native resume synchronously at a safe gesture frontier when no idle transaction is pending. `allowCold: true` permits only a still-frozen zero-time offroute context; the default requires running state. Normal live source7a preparation must use wake: true before clock creation; cold-offroute admission is not a realtime source-clock startup proof. It does not silently recover an interrupted context. Readiness is bounded by a configurable timeout up to 30 seconds, default 10 seconds.

`lease.track(create, release)` records ownership before invoking an asynchronous creation callback. Both callbacks are explicit; release receives the exact returned value. Cancelling aborts the transaction but retains its idle hold until pending creation has returned and every late resource's release acknowledgement has settled. Each ticket admits at most 16 concurrent requests and 64 release actions. Cleanup attempts every resource. An unexpected failed release remains visible and retains its reservation; only an explicit retry re-invokes failed release actions. It is not silently retried while unrelated pending results drain.

`lease.shared(key, acquire)` shares only explicit upstream leases shaped `{context, value, release}`. Keys have one stable acquisition authority, at most 16 distinct keys exist per context, and each ticket's duplicate acquisition is idempotent. Releasing one candidate cannot retire another candidate or a published owner's reference. Only the final reference invokes the supplied upstream release callback. The registry never infers ownership from PCM, consumer counts, source identity or the presence of value.dispose, and never calls a cached global clock's dispose by inference. A callback that fails partway through creation owns its own partial rollback.

`lease.publish(syncCommit)` requires completed preparation, a still-current selection guard and a valid context state. The callback is synchronous and must atomically install the prepared policy/pointers. It returns a resource owner with `retire()`. Publication detaches the preparatory AbortSignal so a late cancellation cannot retire a selected owner. Retirement again holds idle admission through real release acknowledgements. This explicit ownership transfer is not an automatic whole-Generator swap.

`requestContextIdle(context, canSleep)` is called by the installed minimal idleSuspender bridge. With no reservations it performs the existing Native suspend/recheck/resume behavior. With a reservation it blocks new idle requests. If a reservation arrives after Native suspension was already requested, the known pending idle operation resumes before the reservation becomes ready. Native AudioContext methods are never replaced or clock-spoofed.

`contextPreparationStatus(context)` exposes bounded ticket/resource state and a 32-entry diagnostic history. `contextPreparationBlocksIdle(context)` offers a read-only admission predicate. No state belongs to a song or persisted user backend preference.

Twenty registry tests pass: synchronous bounds, in-flight idle ordering, cancellation before readiness, late-result ACKs, shared survivor ownership, synchronous publication, published retirement, stable keys, explicit cold/wake admission, source-independent release callbacks, failed-release retry, stale selection, context closure, request capacity and synchronous cancellation reentrancy. The close fence is installed before abort/release callbacks. A release callback returning that same fence is rejected visibly and retains the hold for explicit retry instead of awaiting itself, including the upstream shared-release callback. Async release callbacks must not await their parent reservation retirement: arbitrary wrapped promise cycles cannot be inferred or safely interrupted by the registry. Six idleSuspender tests preserve its four existing behavior cases and add reservation races; three continuous-policy tests also pass (29 focused checks total).
