# Private owned room host policy

`owned-private-room-framed-500ms-v1` is an opt-in, private captured-IR execution policy. It is not the normal application reverb, a shared send hub, an OfflineAudioContext implementation, or a transparent replacement for asynchronous native room loading/type changes. Existing app and mixer defaults are unchanged.

## One owned path

`createPrivateRoom(context, {convolver, colour, graph}, spec)` prepares a dedicated Worker with the accepted Rust RoomColour/activity and full static convolution kernels, plus a Rust Graph AudioWorklet for dry delay, dry/wet gains and ordered summing. Native Gain nodes are unity routing only. The Worker receives audio over a dedicated MessagePort from the existing bounded convolver transport; the main thread never relays PCM. The audio-thread graph receives a compact configuration, not the potentially 2,097,152-frame IR or its preparation payload.

The source splits before colour: dry input -> Rust fixed delay -> Rust dry gain; wet input -> Worker Rust colour -> optional Rust ordered stereo-to-mono Light conversion -> full Rust convolver -> Rust wet gain. The graph sums dry first, wet second. Exactly one captured room authority owns the same-rate IR, channel/routing contract, colour controls/activity and complete numeric asset identities. The verified loaders own compiled-Module trust; this helper does not independently hash an opaque WebAssembly.Module.

The original amount law is retained: below 0.5, dry=1 and wet=2xamount; otherwise dry=2-2xamount and wet=1. Gains cross the Float32 parameter boundary. No added compressor, limiter, level normalization or clipping is inserted.

## Clock and activity contract

Before touching a caller's routing, the factory prepares both processors offroute and acknowledges readiness. The caller connects the returned output to its destination and calls `start({startFrame})` with one future 128-frame-aligned absolute AudioContext frame. The returned epoch is the sole source-local origin. It also returns absolute earliest-input/earliest-output frames. Repeated starts, missed render clocks, early nonzero input, late controls, invalid payloads and exhausted transport credits fail explicitly.

Both dry and wet are delayed by

`D = max(2 x blockFrames, ceil(sampleRate x 0.5 / 128) x 128)`.

Default blocks are 2048 frames; D is 512 ms at 8 kHz and approximately 500 ms at the other supported rates. There is no additional mixer block delay. Initial warmup is 128-aligned approximately 250 ms, at least 200 ms, with explicitly authored logical zero-channel / parameter-only colour activity. The initial known-input activity restores the declared one/two source channels. The caller must keep nonzero input silent until that acknowledged earliest-input frame. This is an explicit startup policy, not a hidden arbitrary delay on the wet branch.

Later activity metadata remains owned by the source scheduler: logical input width and independent delay/filter `audio` or `params-only` clocks are never inferred from numerical zero PCM. The captured immutable warmup may not be overwritten. Native RoomColour activity semantics were accepted separately; this policy does not infer native silent-bus/tail flags from an analyser.

`setColour(frame, parameter, value)`, `setActivity(event)` and `setAmount(frame, value)` accept future canonical source-local integer frames. They acknowledge the accepted frame and producer frontier or effective output frame. Amount events are applied at `frame + D`, preserving the intended source-time gain on both aligned branches. Amount updates append strictly after the captured/accepted amount book. A command rejection does not silently clamp or shift its requested frame. Worker and host generations prevent stale messages fulfilling a later run.

The new private policy uses the explicit `chromium-room-colour-authored-activity-framed-f32-128-v3` RoomColour contract. Its event records contain integer `frame`, not native seconds. Additive `push_frame`, `schedule_frame` and `prepare_quantum_framed` methods preserve exact event boundaries, including a native zero-length previous segment when Delay evaluates its target again for the right channel. Canonical F/rate storage is accepted only after checking nearest-integer recovery equals the authored F; the separate framed evaluator uses that integer boundary. The private profile is bounded to one hour. Original native-seconds Event/Gain layout and evaluator remain unchanged; six deterministic PCM goldens from accepted checkpoint `3b6ecfb` prove exact original stereo output at all six rates without depending on Git history in the maintained tests.

The native reference authors its corresponding target at canonical absolute D+F. A preparation-only helper chooses a representable seconds value inside the requested native ceil-frame when needed; it does not shift rendered PCM or round arbitrary original native timestamps. Native-seconds RoomColour profiles remain separate, and their ABI rejects framed handles rather than silently mixing clocks.

## Lifecycle and persistence

IRs cannot be changed in place. Dispose and prepare a new offroute private room to change the captured IR/profile/rate/layout. Supported concurrency is two private rooms per AudioContext, with 32 outstanding acknowledgements per endpoint, 256 accepted runtime source commands, 256 runtime amount commands plus a maximum 256 captured amount events. Each run has a finite, aligned input budget no longer than one hour. Transport failure is terminal; there is no native wet-only fallback, adaptive time shift or dropped-frame recovery.

`savePrivateRoomSpec` / `loadPrivateRoomSpec` serialize the complete captured IR and cold replay authority deterministically. `capturedSnapshot()` preserves constructor configuration; it deliberately does not claim to be a running filter/FFT/transport snapshot or automatically include subsequently acknowledged runtime commands. Callers own any later event-log projection. The review page builds an explicit complete replay book for its accepted commands, persists it with source PCM in IndexedDB, closes/reopens the database, and offers a new-page/new-context replay button. This is separate from normal application persistence policy.

`await dispose()` returns one cached cleanup Promise. It rejects outstanding requests, disconnects owned routes, terminates the private producer and waits for both mix/transport disposal acknowledgements before closing ports (one-second fallback). Its quota stays reserved until both acknowledgements and Worker termination settle, preventing rapid offroute rebuilds from overbooking prepared rooms. A delayed-acknowledgement regression checks this ordering. Factory/start failure also waits for owned cleanup before rejecting. Startup cancellation, concurrent preparation failure, failed registration retry and spontaneous mixer failure have focused regression coverage. Original fatal producer/mixer diagnostics are retained before cleanup so a secondary transport disposal cannot mask the cause.

`node tools/auditPrivateRoom.mjs` privately builds instrumented Wasm (no native executable). All 12 full3s/Light2s six-rate cases with two independent complete pipelines pass: all three Rust allocation/reclamation counters remain zero during processing, timestamped commands and reset; no Wasm memory grows. This does not bound JS messages/serialization, arbitrary maximum-IR pairs, browser memory overhead or physical-device deadlines. The existing accepted long-IR kernel separately declares up to 2,097,152 taps and approximately 329 MB Wasm for two maximum stereo handles; the current desktop pair gate must not be advertised as a phone memory guarantee.

The fixed desktop page is `tools/private-room.html`. Bounds were declared before its first native probe: maximum absolute and relative RMS error each 1e-4. The first native batch retained all 12 results; 44.1/48 kHz showed material differences, while the other rates were within bounds. The correction is isolated to the new framed facade. The first representable-ceil correction reduced the errors but four native cases still failed. A separate native stage capture proved dry gain exact and isolated the remaining difference to the colour **right channel at the exact predelay onset**. The native absolute event had an exact integer secondsxrate boundary; the local adjacent representation was slightly below it, skipped the old zero-length segment, and advanced the right target recurrence differently.
