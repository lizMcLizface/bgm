## Literal source contract

`src/synths/effects/graph.js` connects input -> trim -> external stages -> processed -> output, and input -> bypass -> output. Its initial calls use scheduled `setValueAtTime`; later calls use `setTargetAtTime` with .012 seconds. Every call reads `context.currentTime` separately. The three authored values, in original order, are:

- trim: `10 ** (input / 20)`;
- processed: `enabled && !busy ? mix * 10 ** (output / 20) : 0`;
- bypass: `enabled ? (1 - mix) * 10 ** ((input + output) / 20) : 1`.

Each new Gain starts with intrinsic 1, without an assignment step or .02 target. All three initial commands reserve capacity and publish in that order before any program input connects. Subsequent whole-patch reservations preserve every repeated target and each separate time read. A partial publication is terminal; cancellation removes only unwritten reservations.

The full admitted bypass range reaches `10 ** (24 / 20)`, about 15.84893. A separate gain16 Rust ABI reuses the pinned accepted Timeline and Gain/mix arithmetic. It does not modify or widen nominal gain4 profiles. Trim remains physically before the external nonlinearity. Processed and bypass Gains remain after it; no trim distribution or feedback/extra quantum is introduced.

## Activity, clocks and ownership

The new ABI separates authoritative clock observation from unpulled, parameters-only and audio processing. Unpulled observations do not prepare Gain timelines. Active numeric zeros do not establish silence. A private, separate 128-sample integer header repeats producer identity, canonical Source7a frame, channel layout and logical Native Gain activity. Every word and repetition must agree in the current callback before Timeline/DSP advances. This is logical Gain activity, not certification of arbitrary Native bus flags.

Only actual privately constructed continuous review worklets can supply the first composition. The memoryless polynomial is a numerical nonlinear placement fixture, not a replacement for an application effect. Its healthy callback always returns true, including zeros. Existing FX public node shapes, Native Gain wrappers, opaque IIR/tails and caller-supplied factories/certificates refuse. A future FX issuer also needs a privately owned managed attachment/demand handshake; a raw output borrow alone is insufficient.

Every new actor has a dedicated, always-zero output connected directly to the destination for clock/control observations. It does not rely on a zero-gain bridge continuing to pull. Program and activity outputs remain distinct. The declared DSP pull mode remains independent of this observation anchor. Live roots explicitly resume before creating their running Source7a generation; no live cold0 authority is inferred. Virgin Offline contexts use the accepted explicit offline-freeze-v1 policy.

The separate budget is two pairs/four Gain actors per context, alongside the unchanged general four-cohort budget. Review producers have a separate fixed eight-actor bound, and output borrows are capped at eight. Constructors return a synchronous draft owning their Native prefix; readiness/binding observations are bounded. Failed/unknown cleanup holds pair capacity and parent clock until real clean receipts or actual context close. Late cleanup never resurrects a failed Promise.

Normal retirement publishes the literal terminal gate and retains all incoming audio/header edges until the actor's real SourceACK. Disposal runs serially: mix ACK, external ACK (returning its trim borrow), trim ACK, then parent clock and pair capacity. Primary failures and unclean fulfilled dependency receipts remain visible. The adversarial review additionally requires an actual terminal callback before input withdrawal and two physically isolated terminal callbacks while Rust, reader and clock remain unadvanced and unfreed.

## Remaining adoption boundary

This acceptance covers the explicit, continuously observed review composition and its immutable internally owned nonlinear stage. It does not certify arbitrary Native fan-in/activity/tails, external rewire/clear policies, stateful FX activity under silent input, or an application rack switch. Existing ordered bus/space cohorts know logical sum silence internally but expose only physical always-true audio; faithful application input must propagate that logical result through a NEW cohort/header and trim-input profile. A future managed FX issuer must consume/emit the appropriate same-frame activity contract and own attachment/demand lifetime, not merely lend a public raw AWP. Return-hub/dry7 and that application join are separate future profiles; current accepted app/5fd sources remain unchanged.
