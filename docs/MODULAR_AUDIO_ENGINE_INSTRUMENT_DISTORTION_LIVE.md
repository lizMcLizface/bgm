# Original Distortion prepared live host

This separate optional host composes the accepted original Distortion resource law with real Rust audio worklets. No Instrument factory hook or general live GUI adoption is selected by this leaf.

## Control and resource contract

Drive is a finite original value in [0,30]. The original law generates 44,100 Float32 cells in the frozen Rust numerical Wasm, inside a dedicated worker. No host `Math.sinh`/`Math.atan` curve preparation or Native coefficient getter feeds the renderer. The worker reuses one Wasm memory; it permits at most two in-flight and eight total requests, retains typed owner/version identity, and positively frees Rust state before its independent Worker termination.

Each audio engine preallocates eight curve slots, including both literal original constructor-zero resources. Slots have monotonically increasing uint32 generations. Uploads are ordered, at most two chunks await ACK, and the whole rendering callback can copy at most 1,024 floats. A 44,100-cell upload therefore needs at least 44 callbacks. Curve history and active/queued references prevent reuse. The frontend additionally pins opaque prepared handles through actual application ACK or cancellation. A stale, foreign, consumed or wrong-value token is refused. Inactive, unqueued and unpinned slots are reclaimed only after real release acknowledgement; no blind LRU replacement occurs.

Constructor resources are explicitly prepared before AudioWorklet construction. `factory.preparePreset({drive,amount})` returns an opaque same-factory/context single-consume recipe, supplied as `preparedPreset` at construction. Original constructor-zero assignments and subsequent actual setter calls remain separate. This avoids waiting for callback uploads on a suspended or not-yet-rendered Offline context.

For a running actor, `prepareDistortion(value)` returns an owner-bound READY handle; `setDistortion(value,handle)` commits only that ready generation. Whole-preset handles reserve the curve and both gain records before target mutation. Their convenience operation is explicitly curve→dry→wet; a future Instrument adapter must preflight globally then preserve its own original individual setter order, which may be amount→drive. A NEW upload is refused before slot/handle/worker/control mutation until an actual constructor-ready port receipt exists and the live context is running, or an Offline render has advanced to canonical service. Reusing already-READY resources and preprepared constructor recipes is legal before rendering. `.ready` means client/Node construction, not an actual resident-resource or fresh consumer certificate. Live callers arm after resume; the Native reference review obtains a same-port stats/construction fence at its already scheduled first Offline pause before new uploads, without advancing frames. An unprepared arbitrary drive is refused; it does not silently retain the previous curve or rebase its author time. Repeated assignments remain real commands even when resource contents can be reused. Original amount calls retain two independent dry-then-wet `currentTime` reads, repeated calls and exact `dry = 1 - value`, `wet = value` branch/order. Stored drive is a valid getter. Synchronous Native `getAmount()` remains explicitly unsupported; asynchronous stats expose observed values without pretending they are the original getter.

The host transports at most 32 acknowledged raw-Float64 commands using the existing stamped word codec. Audio processing binds the accepted Source7a Native clock. Initial readiness is construction readiness; actual live `arm()` requires a fresh consumer clock, required control watermark and exact realized physical route receipt. Offline pre-render arm is separately labelled preparation-only. Future metadata can wait transactionally only while the private input is genuinely absent; active clock/admission guards remain strict.

## Audio and ownership

The None shaper has zero intrinsic latency and independently processes each declared mono/stereo channel. Its original even grid yields negative DC at zero input. Connected zero and ended sources therefore continue shaping; no automatic Native tail/sleep state is inferred. Explicit private OFF/OPENING is distinct and leaves audio DSP unpulled. Physical route intent uses the frozen shared routeTag protocol: actual falling input is fully processed as DRAIN, OFF requires matching zero-input proof, and a rising reconnect permit is earned only by actual absence. No zero-PCM heuristic is used.

A one-way terminal gate is published before any own graph disconnection. Terminal callbacks emit zeros without DSP/clock decoding; only the actual disposal handler releases Wasm and emits its typed terminal ACK. Source clock links remain held through that ACK. Dedicated preparer free/termination and audio Source retirement are separate authorities, aggregated before successful disposal. Audio failure remains distinct from clean resource release. The quota is four owners per context and remains held until both source and preparer resources are proven released. There is no all-JavaScript-heap or universal device-headroom claim.

The processor requires the exact three-field host/kernel/uint32-owner identity. Terminal messages require exactly `kind` and that identity; malformed/foreign requests do not free state. Facade receipt matching also rejects extra fields. These guards were consolidated after the first browser pilot, without changing the entire healthy DSP/resource/clock bridge.
