Rust graph worker prototype · M3e / M3f / M3g / M3h

Six real instruments, explicit Rust mixing and kick-keyed compression. Choose a complete-graph worker or three source workers with a dependent Rust master. An AudioWorklet consumes fixed PCM buffer pools. This is a dry reference mix. The desk and its defaults remain on the six-role comparison page.

Default pool: 4 × 1,024 frames, 256 KiB. Added buffering: 92.88 / 85.33 / 42.67 ms at 44.1 / 48 / 96 kHz. Missing audio becomes silence; expired blocks are discarded. No shared memory or cross-origin isolation required for this transport. Messaging can allocate and add jitter. Single-worker and three-worker timings are observational; no speedup is established.

M3f groups: lead + bass, second + rhythm, pad + drums. Three workers own their source graphs; one Rust master in the worklet handles the dependent mixing and kick key. At the default profile, three fixed pools total 768 KiB with a 4,096-frame delay. Other profiles keep the same groups and processing. If any group is missing, all program/key inputs for that source frame are silent. Live event owners stay within one group. This prototype does not distribute arbitrary graphs or desk effects.

Profile measurement takes about 3½ minutes at the selected sample rate: one full warmup per profile, then three measured repeats per profile in rotated order. Keep this page active and avoid other benchmark work. Missed/incomplete runs are retained. M3h measures contiguous ready source frames at quantum entry, per worker and coherent minimum, with planned final draining separate. This does not measure device crackles. Worker task times and optional worklet wall time have separate scopes; unavailable clocks are reported. Smaller profiles remain opt-in; the default stays 4096 frames.

Playback is finite: 17.5 seconds plus declared buffering. Startup failure falls back to serial with the same buffering. A failure after playback starts stops this run; a fresh serial run is available above. Live controls must target frames the worker has not rendered yet. Reset/reload creates a new generation and graph.
